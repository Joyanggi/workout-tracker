## §1. Opus 작업 — R1~R5 (전부 소규모, 한 라운드)

### R1. 구백업 복원 shim (REVIEW-VERDICT F3, 중간)

`parseBackup`에서: 루틴의 `fallbackDays[].recordDayId`가 없고 해당 fallback id가
번들 정의(`routine-v2.4.json`)와 일치하면 번들 값으로 채운 뒤 `validateRoutine`을 돌린다.
검증 완화 금지. 테스트: recordDayId 없는 구형 백업 픽스처 → 복원 성공 + 값 보정 확인.

### R2. seedRevision + 해시 스냅샷 테스트 (F4, 낮음)

- 시드 JSON에 `seedRevision: 1` 추가, `ensureSeed`가 version 대신 이것을 비교
- 테스트: 번들 루틴 JSON의 내용 해시 스냅샷 — 해시가 바뀌었는데 seedRevision이
  그대로면 실패 (메시지: "시드를 고쳤으면 seedRevision을 올려라")
- "매 부팅 재주입"은 금지 (사용자가 같은 id로 가져온 루틴을 덮어씀)

### R3. applySubstitute 원상복귀 클리어 (F5, 낮음)

`next.recordKey === (entry.substituteFor ?? entry.recordKey)`이면 `substituteFor: undefined`.
테스트: 대체 → 원 종목 복귀 시 자기참조가 남지 않는다.

### R4. "마감하고 새로 시작" stale 프리필 (REVIEW.md 잔여 1건)

`HomeScreen.startPending`: `finishSession()` 후 `create()`가 useLiveQuery 클로저의
낡은 `sessions`를 쓴다 → 방금 마감한 세션이 새 세션 프리필에 반영 안 됨.
수정: `finish()`가 반환하는 세션을 `create`에 합류시키거나, finish 후 `db.sessions`를
직접 재조회해서 전달. 테스트: 마감 직후 시작한 세션의 프리필에 직전 기록 반영.

### R5. 드래그 재정렬 — 공식 연기 문서화 (P2-1 정리)

**구현하지 말 것.** 근거: 수행 순서 분석은 `performedOrder`가 이미 담당하고, 카드는
아무 순서로나 탭해서 시작 가능하므로 드래그는 시각 정리 이상의 가치가 없다.
iOS 터치 드래그 구현 복잡도 대비 효용 미달. → DESIGN.md §5.2의 해당 줄에
"v1에서 의도적으로 제외 (performedOrder가 순서 분석을 담당)" 주석을 달아
스펙과 구현의 불일치 상태를 해소한다.

완료 시: 전 테스트 통과 + `npm run build` (tsc 직접 호출 금지) + REVIEW-VERDICT.md의
F3~F5 항목에 완료 표시. **이 라운드로 "알려진 결함 0"이 된다.**
