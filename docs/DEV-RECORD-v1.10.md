# 개발·테스트 내역 (검토용) — v1.10 (EE3 · EE1 · EE2) · 2026-11-03

> EE3(복귀 배너 두 칸 선택)·EE1(저녁 다리살)·EE2(단백질원 짝 연동, §9)를 기록한다. PLAN-v1.10의
> 세 작업이 모두 끝났고, EE2 커밋에서 package.json을 1.9.1 → **1.10.0**으로 올렸다.

## 이 환경에서 확인된 제약 (누적 — 매 라운드 맨 위에 둔다)

1. `npx tsc --noEmit`은 `src`를 검사하지 않는다 → **`npm run build`로 타입 확인**.
2. 개발 브라우저 창은 `visibilityState`가 항상 `hidden`이다 → 소리가 들리지 않고, rAF·focus
   이벤트가 발화하지 않고, 250ms/80ms 인터벌이 ~1Hz로 스로틀된다.
3. vitest에서 `.css`를 `?raw`로 읽으면 **빈 문자열**이 온다 → 색·크기는 브라우저
   `getComputedStyle` 실측으로 확인한다 (이번 라운드에서 diff 줄 대비 6.28:1을 그렇게 쟀다).
4. `computer` 클릭은 pane이 hidden이면 타임아웃된다 → 조작은 `javascript_tool`로 한다.
   **단 `screenshot`은 hidden에서도 찍힌다** (이번에 ▾ 버튼 판정에 그게 결정적이었다).
5. React 렌더 테스트(RTL)가 없다 → 화면 규칙은 **순수 함수 + 소스 스캔** 2층으로 잠근다.
6. `javascript_tool`로 React 이벤트 일부를 재현할 수 없다: `.click()`은 `onPointerDown/Up`을
   발화시키지 않고(→ `PointerEvent` 디스패치), `blur()`는 포커스 없는 문서에서 이벤트를
   만들지 않는다(→ 버블링 `focusout`). **이번 라운드의 버튼들은 `onClick`이라 `.click()`으로
   충분했다.**
7. 소리는 이 창에서 들을 수 없다 (제약 2) → 오디오는 단위 스펙 + `createOscillator` 후킹.
8. `git checkout <파일>`은 커밋되지 않은 작업을 버린다 → 되돌리기는 `cp` 백업으로 한다
   (v1.9에서도 시드 편집 전에 백업을 먼저 떴다).
9. **새로 확인:** `innerText` 부분 문자열 매칭으로 요소를 고르면 안 된다. `find(c =>
   c.innerText.includes('올리브오일'))`이 **닭다리살 칩**을 잡았다 — 그 칩의 문구가
   "200g · 그날 올리브오일 생략"이기 때문이다. 한 번 잘못된 측정값(kcal 330)을 만들었고
   그건 앱 결함이 아니라 **내 선택자 결함**이었다. 인덱스나 정확 일치로 고른다.

10. **새로 확인 (EE3 라운드):** 이 브랜치에 들어올 때 EE3 구현과 테스트는 **이미 `e2d7093`에
    커밋돼 있었다.** 이번 작업은 구현이 아니라 PLAN 검증 항목 대조 · 결함 복원 확인 · 기록이다.
    작업 시작 전에 `git log`와 `grep returnChoiceReason`으로 먼저 확인했다.
11. **새로 확인 (EE2 라운드):** 이 환경의 Bash 도구에서 `python - <<'EOF'` heredoc 본문이 길고
    작은따옴표·백슬래시가 섞이면 셸 파싱이 깨진다(`unexpected EOF while looking for matching`).
    긴 테스트 코드·스크립트는 **파일로 먼저 쓰고**(scratchpad) 그 파일을 실행·`cat >>`한다.
    커밋 메시지 heredoc(`git commit -F - <<'MSG'`)은 문제없었다.

## 2. EE3 — 라벨 문법을 없애고 답을 두 칸으로

진단은 PLAN 그대로였다: 한 칸 토글의 글자가 상태("적용됨")와 동작("무시")을 번갈아 말했고,
눌러도 카드가 "가볍게 복귀합니다"를 유지했다.

- 배너: `.banner-choice`(`role="group"`) 안에 `[적용] [안 함]`. 각 버튼이 값을 그대로 넣는다
  (`setApplyReturn(true|false)`), 고른 쪽이 `aria-pressed`.
- 카드: `returnChoiceReason({ suggestionReason, gapDays, hasReturnStep, applyReturn })`가
  "안 함"이면 `N일 공백 — 복귀 프로토콜 없이 평소 강도로 시작합니다`를 돌려준다.
  제안 없음·`gapDays: null`이면 제안 근거 / 일수 없는 문구로 폴백.
- 상태는 컴포넌트 상태 — 저장하지 않는다 (AA1 `pickedDayId`와 같은 결).

  (미기록 슬롯은 키가 없다).
  우선순위 ① 그 슬롯의 기록 > ② 같은 날 짝 슬롯 **기록**에서 파생된 짝 > ③ 기억값 > ④ 0.
- 짝 표: `lunch.chicken-2 ↔ dinner.chicken-3`, 다리살(2) ↔ 안심(1). 가슴살(0)은 짝 없음 → ③.
- `variantChoicesFor`는 선택 인자 `today`를 받아 `pairedVariant`를 거친다 (기존 3인자 호출·v1.9 테스트 그대로).
- `seedVariantChoices`가 **같은 규칙**으로 새긴다. 화면이 짝(안심)을 보여줬는데 기록이 기억값(다리살)을
  새기면 v1.9의 결함 B(화면과 판정이 갈림)가 되살아나므로, PLAN의 "기록되는 순간 seedVariantChoices가 화면의
  선택을 새기는 것은 그대로다"를 이렇게 지켰다. 시그니처는 그대로라 v1.9의 초크포인트 스캔도 그대로 통과한다.
- 편집기: 카드 표시와 변형 시트 두 곳의 `variantChoicesFor`에 `todayVariantChoices(day)`를 넘긴다.
- 오일·아몬드 슬롯은 건드리지 않는다. 두 끼 다리살을 막지 않는다 (범위 제외 그대로).

### 9.4 PLAN에 없는 세부 판단 (리뷰어 확인 요청)
1. **짝은 짝 슬롯의 "기록"에서만 파생한다.** 짝 슬롯이 미기록이면 그 슬롯의 기억값이 다리살이어도 짝을 만들지
   않는다 — PLAN ②의 문구("짝 슬롯의 기록에서 파생된")를 그대로 읽었다.
2. **새기기의 짝은 들어온 기록 스냅샷에서 파생한다.** 한 번의 `seedVariantChoices` 패스에서 점심·저녁이
   함께 처음 기록되면(UI 경로로는 생기지 않는다) 막 새긴 점심 값이 저녁의 짝이 되지 않는다 — 두 슬롯 모두
   화면이 그렸던 기억값을 새긴다.
3. **짝은 인덱스 표로 정했다** (PLAN 시그니처에 품목 정보가 없다). 인덱스의 뜻(0 가슴살·1 안심·2 다리살)이
   두 플랜의 점심·저녁에서 같다는 것을 데이터 대조 테스트로 잠갔다.

### 9.7 과거 판정 불변
- 판정(`summarizeDietDay`)은 여전히 **기록된 `variantChoices`만** 본다. `pairedVariant`는 표시와 새기기
  경로에서만 쓰이고, 새기기는 이미 기록된 선택을 덮지 않는다(테스트 "이미 기록된 저녁 선택은 짝이 덮지 않는다",
  v1.9 "이미 기록된 선택을 덮지 않는다") → 과거 날짜의 마크로·점수는 변하지 않는다.
- 미기록 슬롯에 기록을 만들지 않는다(G 결함에서 v1.9·v1.10 테스트 둘 다 실패).
- 시드·DB 스키마·내보내기 코드 변경 없음. EE1의 "변형 추가 전에 기록된 저녁 슬롯의 마크로가 변하지
  않는다"(1781kcal·166g)와 v1.9 전체 테스트가 그대로 통과한다.

### 9.11 실기기 확인 목록
1. `cut-1800-u`에서 점심을 **다리살**로 기록 → 저녁 카드가 기록 전 **닭안심 270g**으로 보이는지.
2. 점심을 **안심**으로 기록 → 저녁 카드가 **닭다리살 320g · 그날 점심 오일·오후 아몬드 생략**으로 보이는지,
   오일·아몬드 체크가 그대로인지.
3. 점심 **가슴살** → 저녁은 마지막으로 고른 저녁 단백질원(기억값) 그대로인지.
4. 저녁을 먼저 다리살로 기록한 날 점심 카드가 **닭안심**으로 보이는지.
5. 짝으로 보인 저녁을 체크하면 하루 kcal가 그 변형으로 계산되는지(화면 = 판정), 저녁 "바꾸기 ▾" 시트의
   선택 표시가 카드와 같은지.
6. 저녁 바꾸기로 다리살을 고르면 점심 다리살 날에도 막히지 않고 합계가 그대로 올라가는지.
