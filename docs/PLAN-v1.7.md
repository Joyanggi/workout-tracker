# PLAN v1.7 — 폴리시 라운드 (BB1~BB7)

> 작성: Fable (리뷰어), 2026-08-05. 구현: Opus.
> 출처: 상용 1군 앱(Strong·Hevy·플랜핏) 대비 UI/UX 평가에서 나온 개선 7건.
> 이 라운드는 기능이 아니라 **마감**이다 — 동작을 바꾸는 항목이 없고(BB6의 힌트 제외),
> 전부 "덜 다듬어진 것"을 다듬는다. 점수·판정·데이터 형식 불변, **소급 효과 없음**이
> 이 라운드의 인바리언트다.
>
> 평가에서 확인한 사실: 입력 마찰·정보 구조는 상용 1군과 동급이거나 우위. 깎인 것은
> 시각 완성도(이모지 탭바, 점선 카드, 완료 행 무반응)와 소소한 낡음(v1.1 라벨)이다.
>
> ⚠ **이 라운드의 공통 함정**: CSS는 vitest로 잠글 수 없다 (`?raw`가 빈 문자열 —
> 누적 제약 3). 화면 규칙은 전부 "순수 함수 + 소스 스캔" 2층(v1.6 §6-14)으로 잠그고,
> **색·크기 값 자체는 브라우저 실측**으로 확인한다 (G6 방식).

## BB1. 탭바 이모지 → 인라인 SVG 아이콘

**현재**: `TabBar.tsx`의 `TABS[].icon`이 문자열 이모지(🔥🍽️📅📈⚙️). OS·폰트에 따라
다르게 렌더되고, 획 굵기·크기가 라벨 타이포와 안 맞으며, active 상태에서 색을 못 입힌다
(이모지는 `color`를 무시한다).

**설계**:

1. `src/components/icons.tsx` 신설 — **의존성 추가 없이** 손으로 그린 인라인 SVG 5개
   (홈=불꽃, 식단=포크나이프, 기록=달력, 분석=꺾은선, 설정=톱니).
   규격: `24×24 viewBox` · `fill="none"` · `stroke="currentColor"` · `strokeWidth 1.8` ·
   `strokeLinecap/Linejoin "round"` · `aria-hidden`.
2. `currentColor` 상속으로 active 탭이 `--accent`, 비활성이 `--text-faint`를 받는다 —
   지금 이모지가 못 하던 것. 라벨은 그대로 유지한다 (아이콘 단독 탭바는 발견 가능성을
   해친다 — 이 앱이 AA2에서 배운 것).
3. lucide 같은 라이브러리를 **넣지 않는 이유**: 아이콘 5개에 의존성 하나는 과하고,
   번들을 아끼려고 recharts까지 지연 로딩한 앱이다 (§2 스택 결정과 일관).

**검증**: 소스 스캔 — TabBar에 이모지 리터럴이 없다(유니코드 이모지 범위 정규식).
아이콘이 `currentColor`만 쓴다(고정 색 금지). 크기·정렬은 브라우저 실측.

## BB2. 완료 세트의 행 전체 상태 변화

**현재**: 세트를 체크하면 **체크 버튼만** 초록이 된다. 행(`.set-row`)은 무반응이라
"몇 세트 남았나"를 훑어 읽을 수 없다 — Strong·Hevy는 완료 행이 통째로 가라앉는다.

**설계**:

1. `.set-row-done` 클래스: 행 배경에 `--ok` 저알파 틴트(rgba(52,199,89,0.07) 부근,
   실측으로 조정) + 세트 번호(`.set-no`)를 `--ok`로.
2. **숫자·스테퍼는 흐리게 하지 않는다.** 완료 후에도 무게·횟수는 확인·수정 대상이고
   (프리필 검증, 오입력 정정), 탭타깃 44px 규칙도 유지된다. 가라앉는 신호는 배경과
   세트 번호가 준다 — 취소선·opacity는 쓰지 않는다 (기록은 지워진 게 아니다).
3. 워밍업 완료 행: `.set-row-warmup`(opacity 0.62)과 겹치면 틴트가 안 보일 수 있다 —
   겹침 상태를 브라우저에서 실측하고, 안 읽히면 워밍업은 세트 번호 색만.

**검증**: 소스 스캔 — 행 클래스가 `set.done`에서 파생된다. 대비·겹침은 실측.

## BB3. 점선 테두리 카드 재설계 (머신 세팅 메모 · 무게 단위)

**현재**: ExerciseCard의 두 진입 버튼이 `border: 1px dashed var(--line)` — 점선은
"아직 없는 것/미완성"의 관례라서, 채워진 뒤에도 placeholder처럼 보인다 (평가에서
"여긴 아직 안 만들어진 곳" 신호로 읽혔다).

**설계**:

1. 점선 → **채운 배경**(`--surface-2`) + 실선 헤어라인. 왼쪽 아이콘(BB1의 SVG 규격으로
   🔧⚖ 대체 2개 추가), 오른쪽 ✎ 유지.
2. **빈 상태와 채운 상태를 테두리가 아니라 텍스트 색으로 구분한다**:
   빈 상태 = `--text-placeholder`("머신 세팅 메모 추가"), 채운 상태 = `--text`(실제 값).
   지금도 텍스트는 그렇게 갈리므로 점선이 없어져도 정보 손실이 없다.
3. `.ex-card-orphan`의 점선은 **유지한다** — 그쪽은 "루틴에서 사라진 종목"이라는
   실제 예외 상태라 점선의 관례가 맞는 자리다. 스코프는 세팅 진입 버튼 2종만.

**검증**: 실측 스크린샷 전후 비교. 소스 스캔 — 세팅 버튼 셀렉터에 dashed가 없다.

## BB4. 홈 배너 스택 다이어트 — 최상위 1개 + 접힌 나머지

**현재**: 복귀 > 디로드 > 백업 > Phase > (증량 · 보상작용) 우선순위 배제 규칙이
이미 있지만 전부 독립 렌더라, 이론상 **배너 3~4개가 동시에 쌓인다**
(예: 백업 리마인드 + 증량 + 보상작용). 스크롤 첫 화면이 경고로 가득 차면
어느 것도 읽히지 않는다.

**설계**:

1. **순수 함수 `bannerQueue(...)`** (`lib/` 신설) — 지금 흩어져 있는 표시 조건·우선순위
   (`showReturn`/`showDeload`/`showPhase`/reminder/progressions/watches + dismissed)를
   한 곳으로 모아 **정렬된 배너 목록**을 반환한다. 우선순위는 현행 그대로:
   저장소 위험 > 복귀 > 디로드 > 백업 > Phase > 보상작용 > 증량.
2. 화면은 **첫 번째 배너만** 펼쳐 보여주고, 나머지가 있으면 그 아래 한 줄
   "다른 알림 N개 ▸" (탭하면 인라인 전개, 컴포넌트 상태). 각 배너의 버튼·나중에(dismiss)
   동작은 변경 없음.
3. **저장소 위험 배너(`storageAtRisk`)는 접히지 않는다** — 데이터 유실 경고는 항상
   보인다 (danger는 큐 밖, 최상단 고정).
4. 기존의 상호 배제 규칙("볼륨 줄여라와 증량하라가 나란히 뜨지 않는다")은 큐 안에서
   그대로 구현한다 — 접기와 별개로, 모순 쌍은 애초에 큐에 안 들어간다.

**검증**: `bannerQueue` 단위 테스트(우선순위·배제 쌍·dismiss 반영) + 소스 스캔
(HomeScreen이 개별 조건이 아니라 큐에서 렌더한다 — 2층 잠금).

## BB5. 설정의 "v1.1" 하드코딩 제거 — 버전 단일 원천

**현재**: `SettingsScreen.tsx:76`에 `v1.1` 리터럴. 실제 라운드는 v1.7이고
`package.json`도 0.1.0으로 방치 — **파생 가능한 값을 손으로 적은 패턴 A**이고,
이 프로젝트가 세 번 잡아온 부류다 (kcalLabel, 커밋 메시지 개수, 시드 해시).

**설계**:

1. `package.json` `version`을 **1.7.0**으로 올리고, 이후 라운드마다 minor를 올리는

2. `vite.config.ts`에 `define: { __APP_VERSION__: JSON.stringify(pkg.version) }` —
   `src/vite-env.d.ts`에 타입 선언. SettingsScreen이 `v{__APP_VERSION__}`을 렌더.
3. 시드 리비전(`routine-v2.4.json`)과는 별개다 — 그쪽은 루틴 버전, 이쪽은 앱 버전.

**검증**: 소스 스캔 — SettingsScreen에 `/v\d+\.\d+/` 리터럴이 없다. 빌드 산출물에
1.7.0이 박히는지 확인 (`dist` grep).

## BB6. 0kg 세트 체크 힌트 — 막지 않고 보여준다

**현재**: 첫 기록 종목에서 무게 0인 채로 체크가 소리 없이 된다 (평가 중 실측).
프리필이 있는 종목에서는 드물지만, **첫 노출 종목·대체 종목에서는 실수 경로**다.

**설계**:

1. **차단하지 않는다.** 운동 중 모달·확인은 적대적이고, 맨몸 예외가 없다고 단정할 수
   없다. 실패의 방향은 현상 유지(X5) — 기록은 되고, 표시만 한다.
2. 순수 함수 `zeroWeightHint(set, isInverse): boolean` — `done && weight === 0 &&
   !inverse`. **inverse 종목은 제외한다**: 어시스티드 풀업의 보조 무게 0은 실수가
   아니라 최고 난도 달성이다 (isInverseKey 체계 그대로).
3. 참이면 그 행의 고스트 텍스트 자리에 `--warn` 색 "무게 미입력" 한 줄 + 무게 숫자를
   `--warn`으로. 체크를 풀거나 무게를 넣으면 사라진다.

**검증**: `zeroWeightHint` 단위 테스트 (inverse 제외 포함) + 소스 스캔(행이 이 함수를
쓴다). 내보내기·분석은 손대지 않는다 — 0kg 세트의 볼륨 기여가 0인 것은 이미 산술이 맞다.

## BB7. 차트 터치 툴팁 폴리시

**현재**: 종목 히스토리 차트(recharts)가 기본 툴팁 스타일 — 밝은 배경/작은 활성점이
다크 테마·터치 환경과 안 맞는다.

**설계**: 토큰 기반 툴팁(`--surface-2` 배경 · `--line` 테두리 · 12px) 공용 스타일 하나를
차트 전부(A그룹 추이·감각 점수·주간 수행·종목 히스토리)에 적용. 활성점 반지름을 터치
기준으로 키우고(r≥5), `allowEscapeViewBox` 기본 유지로 화면 밖 잘림 방지. recharts
지연 로딩 경계는 건드리지 않는다.

**검증**: 실측 (터치 시 툴팁 가독성). 로직 변화 없음.

## 기각 1건 — 라이트 테마 (평가 7번의 앞부분)

**기각 근거** (재론 방지 기록):

1. **DESIGN.md §9의 명시적 결정과 충돌한다** — "다크 테마 고정 (헬스장 환경)"은
   실수가 아니라 근거 있는 선택이었다. global.css 1행이 그 결정을 인용하고 있다.
2. **G6의 대비 실측 자산이 다크 기준이다.** 라이트 팔레트는 전 토큰 재실측이고,
   이후 모든 색 변경이 두 팔레트 유지가 된다 — CSS는 테스트로 잠글 수 없는 영역이라
   (누적 제약 3) 유지 리스크가 배가된다.
3. 사용자 1명·주 사용처(헬스장·저녁)에서 다크가 맞고, 밝은 곳에서도 고대비 다크는
   읽힌다. **낮에 식단 탭을 쓸 때 실제로 불편하다는 보고가 나오면** 그때 그 근거로
   재론한다 — 지금 넣는 것은 없는 문제를 위한 코드다.

## 구현 순서와 검증

권장 순서: BB5 (가장 작음) → BB1 → BB3 → BB2 → BB6 → BB7 → BB4 (구조 변경).

- 이 라운드의 인바리언트: **점수·판정·데이터 형식 불변, 소급 효과 없음.**
  DEV-RECORD에 "소급 효과 — 없음" 절로 확인 기재 (v1.2 §6.4 관례).
- CSS 값은 전부 브라우저 실측으로 확인하고 실측치를 DEV-RECORD에 남긴다 (G6 방식).
- 새 소스 스캔은 결함을 되돌려 실패를 확인한다 (v1.5~v1.6 관례).
- `npm run build` / 커밋 메시지 개수는 실행 출력 복사 / heredoc `<<'MSG'`.
- 완료 후 `docs/DEV-RECORD-v1.7.md`.

범위 제외 (재론 방지):
- 라이트 테마 (위 기각 근거)
- 아이콘 라이브러리 의존성 (BB1-3)
- 탭 전환·세트 체크 스와이프 제스처 (iOS 감각 항목 — 이번 라운드는 마감, 새 조작은
  다음 실사용 피드백에서)
- 앱 아이콘·스플래시 재작업 (현행 유지)

실기기 확인 목록 (구현 후):
1. BB1 — 탭바 아이콘이 5개 전부 선명하고, active가 주황으로 물드는지
2. BB2 — 세트 체크 시 행 전체가 가라앉아 보이는지, 워밍업+완료 겹침이 읽히는지
3. BB3 — 메모 없는 상태가 "추가 가능"으로, 있는 상태가 "기록됨"으로 읽히는지
4. BB4 — 배너 2개 이상 상황(백업 리마인드 + 증량)에서 접힘이 동작하는지
5. BB6 — 첫 기록 종목 0kg 체크 → "무게 미입력" 경고, 어시스티드에서는 안 뜨는지
6. BB7 — 차트 터치 시 툴팁이 읽히는지
