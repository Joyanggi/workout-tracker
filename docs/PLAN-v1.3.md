## W1. 자동완성 잔존 — 머신 세팅 메모 입력 (#1)

**증상**: 다른 필드는 해결됐는데 머신 세팅 메모(ExerciseCard 인라인 입력)만 연락처 제안이 남음.

**먼저 조사**: 그 필드가 실제로 `NO_AUTOFILL`을 받고 있는지 확인 (개수 일치 테스트는 통과
중이므로 받고 있을 가능성이 높다 — 그렇다면 속성 문제가 아니라 **iOS가 이 필드를 연락처로
오인하는 다른 신호**가 있다는 뜻).

**실험 사다리** (한 단계씩, 각 배포 후 사용자 확인 — 결과를 이 문서에 기록):

1. **1차 (무해한 조합 일괄)**: ① placeholder·aria-label에서 오인 유발 가능 단어 점검
   ("메모"는 유지 가능하나 "이름"류 단어 금지) ② `autoComplete`를 표준 `"off"` 대신
   비표준 토큰(예: `"nope"`)으로 — iOS가 "off"를 무시하는 사례에서 통용되는 우회
2. **2차**: `type="search"` + CSS appearance 리셋 (검색 필드에는 연락처 제안이 안 붙는 경향)
3. **3차 (최후)**: `readOnly` 기본 + `onFocus`에서 해제하는 고전 트릭 — UX 부작용(첫 탭 반응)
   있으므로 1·2차 실패 시에만

`NO_AUTOFILL` 객체 자체를 바꾸지 말 것 — 다른 15개 필드는 해결됐으므로 이 필드에만
추가 속성을 얹는다 (개수 일치 테스트는 유지).

## ✅ W2. 휴식 타이머 소리 — 틱 미재생 조사 + 차임 강화 (#2)

> **조사 결과 (2026-08-05) — 가설 A·B·C 전부 사망. 원인은 코드가 아니라 음향이었다.**
>
> | 가설 | 판정 | 근거 |
> |---|---|---|
> | A 플래그 공유 | **사망** | `tempoGuide`는 `ExerciseCard`의 ♩ 버튼 노출만 결정한다. 소리 경로(`beep`·`useRestTimer`)에 설정을 읽는 코드가 없다 |
> | B unlock 시점 | **사망** | `unlockAudio()`는 세트 체크 핸들러의 **첫 문장**이고 `timer.start()`보다 먼저다. 틱은 87초 뒤라 컨텍스트가 이미 있다 |
> | C 경로 차이 | **사망** | 가이드 ON/OFF와 무관하게 세트 체크가 같은 `unlockAudio()`를 지난다 |
> | **D 음향** | **확정** | 아래 |
>
> **재현: 스케줄링은 정상이다.** 판정 로직을 순수 함수(`createCountdownTicker`)로 꺼내
> 실제 코드로 돌렸더니 restSec 45·60·75·90·120·150·180초 **전부에서 3·2·1이 정확히
> 한 번씩** 발화한다 (샘플 주기 100~900ms에서도 동일).
>
> **실효 음량을 계산했다.** 330Hz · 80ms · gain 0.16이 차임보다 **약 31 dB 작다**
> (스피커 공진 가정 500~1000Hz 범위에서 26~36 dB):
>
> | 요인 | 틱 (330Hz·80ms) | 차임 (880/1320Hz) |
> |---|---|---|
> | 폰 스피커 저역 롤오프 (공진 아래 12dB/oct) | **−13.3 dB** | −1.5 / −0.3 dB |
> | A-가중 (청감) | **−6.3 dB** | −0.4 / +0.7 dB |
> | 시간 적분 (귀의 창 ~200ms) | **−4.0 dB** | −0.5 / 0 dB |
>
> 31 dB 중 **23 dB가 주파수와 길이**에서 온다. "짧고 낮게 해서 차임과 구분한다"는 v1.2의
> 결정이 **구분에는 성공하고 가청에는 실패**했다.
>
> **⚠ 계획서의 처방을 따르지 않았다.** 게인만 올리는 안(틱 0.16→0.20)은 틱을 **+1.9 dB**
> 올리는 동안 차임을 +3.5 dB 올려서 **격차가 32.9 dB로 벌어진다** — 증상이 악화된다.
> 대신 **구분 근거를 높이에서 형태로 옮겼다**: 둘 다 스피커가 잘 내는 대역에 두고
> 틱은 같은 음 하나(784Hz·110ms), 차임은 올라가는 세 음(880→1175→1568Hz).
> 결과 **틱 +20.5 dB · 차임 +3.2 dB · 남은 격차 14 dB** (차임이 여전히 상위 신호).
>
> **덤으로 잡은 결함:** 가이드 카운트인이 `tone({freq:330,...})`을 **손으로 베껴** 갖고
> 있었다. 틱 주파수를 고치는 순간 카운트인만 옛 소리로 남을 상황이었다 (패턴 A).
> 이제 `tick()`을 호출하고, 소스 스캔이 규격 중복을 금지한다.
>
> **"가이드를 켜면 틱이 들린다"의 정체:** 가이드 카운트인이 **같은 330Hz 틱**이었고,
> 가이드는 폰을 가까이 든 채 조용한 상태에서 쓰므로 같은 소리가 들렸을 뿐이다.
> 코드 차이가 아니다. 그 무관함은 이제 `audioIndependence.test.ts`가 지킨다.
>
> **검증**: 512 테스트 · 네 가지 위반(틱을 설정으로 감싸기 / 규격 베끼기 /
> 틱을 v1.2 값으로 되돌리기 / unlockAudio를 조건 뒤로 밀기)을 일부러 만들어 전부 실패 확인.
> 브라우저에서 **실제 모듈**을 불러 스케줄 확인: 틱 784Hz 단음 · 차임 880→1175→1568
> (0 / 0.18 / 0.36초 오프셋, 상행). 가이드 카운트인 실측 **784·784·784** (1초 간격) → 660Hz 올림.
>
> ⚠ **브라우저에서 소리 자체는 확인 불가**: 이 창의 `document.visibilityState`가
> 항상 `hidden`이라 §5.2 가시성 가드에 막힌다 (틱·차임 둘 다 화면이 켜져 있을 때만 울린다).
> 실기기 확인 1번이 남은 검증이다.

### 원래 계획 (참고)

**증상 (사용자 보고)**: ① 3·2·1 틱이 안 울리고 종료 차임만 울림. **템포 가이드 설정을 켜면
틱도 나는 것 같음** ② 차임이 너무 심플해서 음악에 묻힘 ③ 볼륨 아주 약간 부족.

**먼저 조사 — ①의 원인 (가설 검증 순서)**:
- 가설 A: 틱 재생 경로가 템포 가이드 설정 플래그를 잘못 공유 (조건문·모듈 초기화 확인)
- 가설 B: AudioContext unlock 시점 — 차임은 울리므로 컨텍스트 자체는 살아 있음.
  틱 스케줄이 unlock 이전에 등록되어 버려지는 타이밍 문제인지
- 가설 C: 가이드를 켠 세션에서만 resumeAudio가 충분히 일찍 불리는 경로 차이
- **재현 테스트를 먼저 작성** (가이드 OFF 상태에서 틱 3회가 스케줄되는지 스텁으로) —
  원인을 확정한 뒤 수정. 수정 후 "가이드 설정과 무관하게 틱이 난다"를 테스트로 고정

**차임 강화**:
- 2음 → **3음 상행 아르페지오** (총 ~0.6초, 880Hz대 시작 — 고음역이 음악 사이로 잘 뚫린다)
- 게인: 차임 0.18 → **0.28**, 틱 0.14 → **0.20** ("아주 약간"이 사용자 기준 — 과하면 되돌림)
- 톤 정의는 beep.ts 한 곳 유지, 스텁 테스트의 주파수·순서 기대값 갱신

## W3. 템포 가이드 — repMax 도달 시 자동 종료 + 휴식 자동 시작 (#3)

**증상**: 인클라인(6~10회)에서 30회를 넘어도 가이드가 계속 돈다.

**변경**:
1. 가이드가 `routineExercise.repMax`를 알고, **reps가 repMax에 도달하는 순간 자동 종료**
2. 자동 종료 시퀀스: ① 해당 세트 reps = repMax 기록 ② **세트 체크** ③ 기존 onSetChecked
   경로로 **휴식 타이머 자동 시작** (그 종목 restSec) ④ 시트 닫기 — 사용자 탭 0회
3. **마지막 사이클 진입 시 구분 큐** (고음 더블 틱 + 링 색 변화) — "이번이 마지막"을
   미리 알려야 갑자기 끊기지 않는다
4. 헤더에 진행 표시: `7 / 최대 10회`
5. 수동 종료(조기 중단)는 현행 유지 — 이 경우에만 "약 N회" 라벨 경로 (V1)
6. 설정 토글은 두지 않는다 — repMax 도달 시 계속할 운동학적 이유가 없다. A그룹은 상단
   도달이 더블 프로그레션의 목표 지점이고(문서 10장), B그룹은 "횟수는 목표가 아니라
   결과"(문서 3장)라 상단을 넘겨 끌 이유가 없다. 더 하고 싶으면 세트 체크를 풀고 수정하면 된다

**효과 (설계 노트)**: §6.1의 반복수 인플레이션 경로가 "조기 중단 후 시트 방치"로만 좁혀진다 —
상단 도달 세트는 이제 정확한 값이 자동으로 들어간다.

**테스트**: 자동 종료가 정확히 1회 발화 / reps == repMax 기록 / 세트 done / 타이머 restSec
시작 / 마지막 사이클 큐 발화 시점.

## W4. 휴식 종료 확인 버튼 제거 (#4)

**변경**: 종료 상태(finished)에서 확인 탭 없이 **차임 후 3초 뒤 자동 dismiss** (localStorage
정리 포함). 3초 내에 탭하면 즉시 닫힘 (기존 동작 유지). 다음 세트 체크가 새 타이머를
시작하는 경로는 영향 없음.

**테스트**: finished → 3초 경과 → 상태 idle + persisted 제거. 3초 내 새 타이머 시작 시
자동 dismiss 타이머가 새 타이머를 죽이지 않는다 (경쟁 조건).

## 리뷰어 판단 추가 (1건)

**W5. 가이드 자동 종료와 수동 종료의 기록 신뢰도 구분** — W3 이후 reps 값의 출처가
두 가지가 된다: 자동(정확 — repMax까지 완주) / 수동(추정 — "약 N회"). 내보내기 MD에서
이 구분이 보이면 LLM 분석에서 "상단 도달"과 "중단"을 구분할 수 있다.
`SetRecord`에 필드를 늘리지 말고, **가이드 수동 종료 시에만 세션 메모가 아니라 해당
entry의 sensoryNote 뒤에 자동 덧붙이지도 말 것** — 과설계다. 대신 자동 종료는 reps가
정확히 repMax와 일치하므로 내보내기에서 사후 식별 가능(12/12/12/12 패턴). **코드 작업
없음 — 이 관찰만 기록해 둔다.** (실사용에서 구분 필요가 실제로 생기면 그때 필드 추가)
