# 개발·테스트 내역 (검토용) — v1.6 (AA1~AA3) · 2026-08-05

> 구현: Opus. 계획서: `docs/PLAN-v1.6.md` (Fable).
> 원 피드백 3건 전부 채택·구현·배포 완료. 725 테스트 / 40파일 통과.

## 이 환경에서 확인된 제약 (누적 — 매 라운드 맨 위에 둔다)

1. `npx tsc --noEmit`은 `src`를 검사하지 않는다 → **`npm run build`로 타입 확인**.
2. 개발 브라우저 창은 `visibilityState`가 항상 `hidden`이다 → 소리·rAF·focus 이벤트가
   발화하지 않고, 250ms 인터벌은 ~1Hz로 스로틀된다.
3. vitest에서 `.css`를 `?raw`로 읽으면 **빈 문자열**이 온다 → CSS 규칙은 소스 스캔으로
   검증할 수 없다 (브라우저 computed style로 실측한다).
4. 이 창에서 `computer` 클릭은 pane이 hidden이면 30초 타임아웃된다 → **이번 라운드의
   모든 조작은 `javascript_tool`로 실제 DOM 클릭을 발생시켜 했다.** 렌더 결과는
   `innerText`·`getBoundingClientRect`로 읽고 스크린샷으로 확인했다.
5. 이 프로젝트에 React 렌더 테스트(RTL)가 없다 → 화면 규칙은 **순수 함수 추출 + 소스
   스캔**으로 잠근다 (§6).

## 3. 구현 중 새로 발견한 것 (2건)

### 3.1 [AA3] 지우기의 비대칭 — `applyClearSubstitution`이 없었다

계획서가 신설을 지시했지만, **왜 없어도 지금까지 굴러갔는지**가 발견이다:
대체를 걷어내는 유일한 방법이 `applyClearSlot`(슬롯 전체 삭제)이었고, 그래서
**대체를 지우면 추가·체크까지 함께 사라졌다.** 시트가 대체 편집 폼으로 바로 열려서
"대체 지우기"라는 조작을 상상할 기회조차 없었기 때문에 이 비대칭이 드러나지 않았다.

시트를 열자 결함이 하나 더 보인 셈이다 — **조작을 넓히면 데이터 연산의 구멍이 드러난다.**

### 3.2 [AA3] 표기 사본이 이미 세 곳에 있었다 (계획서에 없는 작업)

계획서는 "메뉴 상단에 현재 상태 요약 — DietDayEditor 카드의 표기를 재사용"이라고 했다.
그 지시를 문자 그대로 따르려고 카드의 표기를 찾았더니 자가 태그 라벨 사본이
**세 곳**에 있었다:

| 위치 | 형태 |
|---|---|
| `DietDayEditor.tsx` | `QUALITY_LABEL` (카드 표기) |
| `DietSlotSheet.tsx` | `QUALITY[]`의 `label` 필드 (입력 폼) |
| `exportMarkdown.ts` | `QUALITY_LABEL` (LLM 내보내기) |

시트에 요약을 인라인으로 적으면 **네 번째 사본**이 된다. 그 자리에서 모았다:

- `types.ts` → `SlotQuality` 타입 (같은 3값을 세 파일이 각자 유니온으로 적고 있었다)
- `lib/diet.ts` → `QUALITY_LABEL` · `substitutionNote` · `additionNote`
- **기존 사본 grep = 0** (`similar: '비슷한 구성'` 정의가 남은 곳 = `lib/diet.ts` 1곳).
  X3에서 세운 관례("모으는 것과 지우는 것은 다른 작업")를 이번엔 **테스트로 강제**했다 —
  사본 개수 스캔이 `['/src/lib/diet.ts']`와 정확히 같기를 요구한다.

내보내기의 **문장 형식은 통합하지 않았다** (`대체: "x" — 태그` vs 화면 `대체: “x” · 태그`).
LLM이 파싱하는 마크다운과 화면 한 줄은 서로 다른 독자를 갖는다. 공유해야 하는 것은
**"이 태그를 한국어로 뭐라고 부르는가"**이고, 그것만 모았다.

## 4. 계획서와 다르게 판단한 것 (3건)

### 4.1 [AA1] 디로드 배너도 "보이는 Day"로 시작한다

계획서: "디로드 배너의 '디로드로 시작'은 그대로 즉시 시작한다."
**1단으로 남기라는 부분은 그대로 따랐고**, 어느 Day를 시작하는지는 계획서가 말하지 않았다.
`suggestion.day`를 그대로 두면 이런 상태가 생긴다:

> 카드에 "Push 축소"가 보이고 시작 버튼도 "Push 축소 시작"인데,
> 그 위 배너의 [디로드로 시작]을 누르면 **Day 1**이 시작된다.

같은 화면의 두 버튼이 다른 Day를 만드는 것은 AA1이 없애려던 결함(경로에 따라 결과가
다르다)과 같은 형태다. `start(displayed, 'deload')`로 바꿨다 — **override가 없으면
이전과 완전히 동일한 동작**이므로 회귀 위험은 override가 있는 경우로 한정된다.

### 4.2 [AA1·AA2] 시트가 자기 역할을 말한다 (계획서에 없음)

조작 모델이 "탭=시작"에서 "탭=선택"으로 바뀌었는데, 시트 자신은 아무것도 달라지지 않는다.
이전 모델을 이미 학습한 사용자(=본인)에게는 **행을 탭하는 것이 여전히 시작으로 보인다.**

- 시트 상단에 한 줄: "고르면 홈 카드가 바뀝니다. 시작은 시작 버튼으로."
- 직접 고른 Day에 **"선택" 칩** (제안 칩과 나란히). 제안 Day에는 붙이지 않는다 —
  그 상태는 override가 없는 상태이고, 두 칩이 같은 행에 뜨면 무슨 차이인지 알 수 없다.

### 4.3 [AA3] "안 먹음"을 대체 행에서 분리했다

계획서는 대체 행을 `[대체 수정] + [대체 지우기]`로 만들라고 했다. 기존 그 행의 짝은
`[대체했어요] + [안 먹음]`이었으므로 "안 먹음"의 자리를 정해야 했다.

조건에 따라 자리를 옮기는 것(대체가 있으면 아래로 밀기)은 **탭 위치가 기록 상태에 따라
달라지는 것**이라 X8에서 문제였던 것과 같은 부류다. 그래서 세 줄로 고정했다:

```
[전부 먹음 (N개)]              ← 주 경로 (primary)
[대체했어요/대체 수정] [대체 지우기?]
[추가로 먹었어요/추가 기록 수정] [추가 지우기?]
[안 먹음]
[기록 지우기?]
```

대체·추가가 같은 모양의 행을 갖고, 그 아래가 예외·정리다. 지우기 버튼의 유무만
상태에 따라 달라지고 **행의 순서와 각 행의 첫 버튼 위치는 고정**이다.

### 이 라운드에 의식적으로 한 것

14. **화면 규칙은 "순수 함수 + 소스 스캔" 두 층으로 잠근다.** 규칙 자체(`pickedIdFor`,
    `displayDay`)는 단위 테스트가 잡고, **화면이 그 함수를 쓰는지**는 소스 스캔이 잡는다.
    AA1의 결함이 있던 자리가 정확히 후자였다 — `onPick={(day) => start(day)}`는 규칙이
    틀린 것이 아니라 배선이 틀린 것이어서, 함수만 만들어 두면 아무도 못 부르는 상태로
    통과할 수 있다.
15. **새 스캔은 결함을 되돌려 실패를 확인한다** (v1.5에서 세운 것을 이어간다).
    5건 전부 확인했다:

    | 스캔 | 되돌린 결함 | 결과 |
    |---|---|---|
    | 초기 mode가 record에 의존하지 않는다 | `record?.substitution ? … : null` 복원 | 2건 실패 |
    | 표기 사본이 lib/diet.ts 하나뿐이다 | exportMarkdown에 사본 재삽입 | 1건 실패 |
    | onPick이 start를 부르지 않는다 | `onPick={(day) => start(day)}` 복원 | 1건 실패 |
    | 카드와 시작 버튼이 같은 파생 Day를 쓴다 | 카드에 `suggestion.day.name` 복원 | 1건 실패 |
    | 텍스트 힌트를 지웠다 | `.today-change` 복원 | 1건 실패 |

16. **"검사가 헛돌고 있다" 메시지를 정규식 추출마다 붙인다.** 소스 스캔의 최악은 대상을
    못 찾아 `undefined`를 통과시키는 것이다. 리팩터링으로 정규식이 안 맞게 되면
    **조용히 통과하는 대신 이름을 대며 실패**해야 한다.

## 8. 내가 스스로 의심하는 것 (리뷰 핵심)

### 8.1 [중간] AA1의 선택 상태가 컴포넌트 상태라 세션 시작 실패 시 사라진다

계획서 AA1-4가 "저장하지 않는다"를 명시했고 그 근거(다음 날 낡은 선택이 남는 것이 더 나쁜
실패)에 동의한다. 다만 **진행 중 세션이 있을 때**의 경로를 확인해 두어야 한다:

`start()`는 `setPickedDayId(null)`을 먼저 하고, `openSession`이 있으면 `pending`에
넣고 `OpenSessionSheet`를 띄운다. 여기서 사용자가 **[닫기]로 시트를 취소하면**
세션은 시작되지 않았는데 override는 이미 지워져 있다 — 카드가 제안 Day로 돌아간다.

- 실해는 작다 (다시 [변경]으로 고르면 된다) 그리고 `pending`은 Day를 들고 있으므로
  **취소 후 재개했을 때 잘못된 Day가 시작되는 일은 없다.**
- 대안은 `setPickedDayId(null)`을 `begin()` 직전으로 옮기는 것인데, 그러면 `start`의
  두 분기(즉시 시작 / pending 경유)에 같은 줄을 각각 적어야 한다 — **결함 B를 만드는
  형태**라서 하지 않았다. 지금은 "시작을 시도하면 override를 놓는다"는 한 줄 규칙이다.
- **묻는 것**: 이 트레이드오프가 맞나. 아니면 `startPending`에서만 지우고 즉시 경로는
  `begin` 직후로 옮기는 편이 나은가.

### 8.2 [낮음] AA2의 [변경] 폭을 84px로 고정했다

`flex: 0 0 84px`. 375px에서 시작 버튼 251 + 변경 84 + 간격 8 = 343 = 정확히 내용 폭
(실측). 근거는 "변경"이 두 글자라는 것뿐이고, **더 작은 화면(320px)에서는 실측하지
않았다** — 시작 버튼 라벨이 "Day 3 — 하체 + 코어 시작"처럼 길면 줄바꿈될 수 있다.

- X8에서 배운 것("줄바꿈은 행 높이를 흔들어 옆 버튼의 탭 위치를 밀어낸다")이 여기도 적용된다.
- 다만 이 앱은 **사용자 기기 하나**를 위한 것이고 그 폭이 375px 이상이다. 320px 방어를
  지금 넣는 것은 없는 사용자를 위한 코드다. **실기기 확인 목록 2번**이 이 검증이다.

### 8.3 [낮음] AA3의 상태 요약이 "체크 상태"를 말하지 않는다

메뉴 상단 요약은 안 먹음·대체·추가만 보여준다. **일부 항목만 체크된 상태**는 말하지 않는다
(카드에 항목 체크박스가 이미 보이므로 시트에서 반복하지 않기로 했다).

시트를 여는 경로가 카드의 슬롯 이름이므로 **바로 위에 체크 상태가 보이는 상태에서** 시트가
열린다 — 그래서 지금은 중복이라고 판단했다. 다만 시트가 화면 하단을 덮으므로 슬롯 카드가
가려질 수 있다. **실기기 확인 목록 3번**에서 이것도 함께 보면 좋겠다.

## 9. 리뷰어에게 묻는 것

1. **§8.1** — `setPickedDayId(null)` 위치. 지금(시작 시도 시점) vs `begin` 직후.
   후자가 정확하지만 같은 줄이 두 분기에 생긴다.
2. **§4.1** — 디로드 배너가 `displayed`를 쓰도록 바꾼 판단. 계획서가 말하지 않은 자리를
   내가 정했으므로 확인이 필요하다.
3. **§3.2** — 표기 사본 통합에서 **내보내기 문장 형식은 남겼다.** 같은 라벨을 쓰되
   문장은 각자인 상태가 맞나, 아니면 `dietSectionMarkdown`도 `substitutionNote`를
   쓰고 마크다운 쪽 인용부호·구분자를 화면과 통일해야 하나 (내보내기 형식 변경 = LLM
   프롬프트 형식 변경이라 조심스러웠다).

## 실기기 확인 목록 (배포 완료 — 지금 가능)

1. **AA1** — [변경]에서 다른 Day를 탭 → **세션이 만들어지지 않고** 홈에 머문다.
   카드가 "직접 선택 — 제안은 …"으로 바뀌고, [{그 Day} 시작]으로 시작된다.
   시트를 다시 열면 그 Day에 "선택" 칩이 붙어 있다. 제안 Day를 고르면 되돌아온다.
2. **AA2** — [변경] 버튼이 시작 버튼 옆에 보인다. **긴 Day 이름("Day 3 — 하체 + 코어")
   에서 시작 버튼 라벨이 한 줄로 들어가는지** (§8.2).
3. **AA3** — 대체를 기록한 슬롯을 다시 열면 **메뉴가 나온다.** 상단에 "대체: …"가 보이고,
   [추가로 먹었어요]로 추가를 기록하면 카드에 "대체: … / + 추가: …" 둘 다 남는다.
   [대체 지우기]로 대체만 걷어내도 추가가 남는다. (§8.3 — 시트가 슬롯 카드를 얼마나 덮나)

> 이번 라운드는 **개발 브라우저에서 세 항목 모두 실제 조작으로 확인**했다 (§부록).
> 실기기 확인은 폭·터치 위치·긴 라벨 같은 **화면 크기 의존 항목**과 iOS Safari 확인용이다.
