## CC1. 간헐적 소리 안 남 — iOS `interrupted` 상태를 복구 경로가 놓친다

**피드백**: "앱 나갔다 오면 소리가 안 난다. 완전 종료 후 다시 켜면 난다."

**확인된 현재 동작**: `beep.ts`의 복구 경로 세 곳(`unlockAudio` 70행, `resumeAudio`
76행, `tone` 136행)이 전부 `state === 'suspended'`일 때만 `resume()`을 부른다.
**iOS Safari는 앱 전환·전화·시리 등에서 컨텍스트를 비표준 상태 `'interrupted'`로
떨어뜨린다** — 그 상태는 세 곳 어디에도 안 걸려서 소리가 죽은 채로 남는다.
완전 종료 후 재시작하면 새 컨텍스트라 정상 — 증상 서술과 정확히 일치한다.

**설계**:

1. 복구 조건을 `state !== 'running'`으로 넓힌다 (`closed` 제외 — 그건 재생성 대상).
   판정을 헬퍼 하나(`needsResume(state)`)로 모은다 — 세 곳이 각자 조건을 들면 다음에
   또 한 곳만 고쳐진다.
2. **resume이 거부되면 컨텍스트를 버린다** (`ctx.close()` 후 `ctx = null`) — 다음
   사용자 제스처(세트 체크가 `unlockAudio()`를 부른다)에서 새로 만들어진다.
   "죽은 컨텍스트를 붙들고 있는 것"이 지금의 실패 모드다.
3. 설정 진단의 `audioContextState()` 한 줄이 이 상태들을 이미 보여준다 — 문구에
   `interrupted`를 앱 쪽 문제로 분류하는 주석(Y3)도 함께 갱신.

**검증**: `needsResume` 단위 테스트 (suspended·interrupted → true, running → false) +
세 경로가 헬퍼를 쓴다는 소스 스캔. 실기기: 세션 중 앱 전환 → 복귀 → 다음 틱·차임 확인.

## CC2. 템포 가이드를 닫아도 틱이 하나 더 울린다

**피드백**: "마지막 템포가이드 내림 후에도 1틱 사운드 남."

**원인 방향** (구현이 확정할 것): `tone()`은 `osc.start(at)`로 **예약**한다 — delay가
있는 톤(차임 2·3음, 마지막 큐 2음)과 방금 예약된 페이즈 톤은 시트를 닫아도 이미
오디오 그래프에 올라가 있어 그대로 재생된다. React 정리는 예약을 취소하지 않는다.

**설계**: `beep.ts`에 **태그 기반 예약 취소**를 넣는다.

1. `tone(spec, tag?)` — 만든 oscillator를 태그별로 추적하고, `stop()` 예약 시점에
   목록에서 비운다. `cancelTag(tag)`는 그 태그의 노드를 즉시 `stop()` + disconnect.
2. 템포 가이드의 모든 소리(페이즈 글라이드 CC7 포함, 카운트인 틱, 마지막 큐)는 태그
   `'tempo'`, 휴식 타이머 소리(틱·차임)는 태그 `'timer'` — 가이드를 닫을 때
   `cancelTag('tempo')`가 **동시에 울리고 있을 수 있는 휴식 차임을 건드리지 않는다.**
3. TempoGuideSheet 언마운트 effect에서 `cancelTag('tempo')`.

**검증**: cancel이 해당 태그만 멈추는 단위 테스트 (Web Audio mock — beep.test 기존
방식) + 가이드 언마운트가 cancel을 부른다는 소스 스캔.

## CC3. 휴식 타이머 단독 시작

**피드백**: "휴식시간만 단독으로 타이머 기능 킬 수 있으면 좋겠음."

**설계**: 세션 화면 헤더(종료 옆)에 타이머 버튼 → 작은 시트: **열려 있는 종목의
`restSec`이 기본 선택** + 프리셋 60/90/120/150/180초 → `timer.start(sec, '수동')`.
기존 `useRestTimer`(App 소유)와 RestTimerBar를 그대로 쓴다 — 새 타이머 개념을 만들지
않는다. 세트 체크와 무관하게 언제든 시작·연장·건너뛰기 가능해진다.
홈·다른 탭에는 넣지 않는다 — 사용 맥락이 세션 중(자리 이동, 스트레칭)이다.

**검증**: 시트 → start 배선 스캔. 나머지는 기존 타이머 테스트가 커버.

## CC4. 템포 가이드에 호흡 표시

**피드백**: "시간과 함께 호흡도 알려주면 좋겠음" + 7번 참고사항 ("B그룹 짜내기·늘리기
호흡을 모르겠다, 3초 들숨 3초 날숨은 생각보다 길다").

**원본**: 루틴 문서 3장 템포 규정 표에 **호흡 열을 추가했다** (2026-08-05) — 원리는
"힘쓸 때 내쉰다" 하나. 3-in/3-out 같은 대칭 호흡이 아니다.

**설계**: `tempo.ts`에 `BREATH_LABEL: Record<TempoPhase['kind'], string>` —
`concentric: '내쉬기'` · `squeeze: '마저 내쉬기'` · `eccentric: '들이쉬기'` ·
`stretch: '들숨 유지'`. 가이드 중앙의 페이즈 라벨 아래 한 줄로 표시
("이완 · 들이쉬기"). 색·소리는 붙이지 않는다 — 소리 채널은 CC7 글라이드가 쓴다.

**검증**: 라벨 매핑 단위 테스트 + 문서 표와의 일치를 이름 붙은 테스트로
("호흡 규정은 문서 3장 표가 원본이다").

## CC5. 레그 컬 템포에 수축 정지가 빠져 있다 — 종목별 템포 오버라이드

**피드백**: "레그컬 운동 팁에 수축정지 있는데 템포는 수축정지 안 함."

**확인된 현재 동작**: 정확하다. `exercises.json` leg-curl cue = "수축 지점에서 1초
정지"인데 leg-curl은 **A그룹**이라 템포가 수축1-이완2 (정지 없음). 템포는
`TEMPO[group]` 그룹 상수뿐이라 종목 예외를 표현할 수 없다.

**원본**: 문서 3장 템포 표에 **예외 행(레그 컬: 1-1-2)**을 추가했다.

**설계**:

1. `Exercise`(catalog)에 `tempo?: TempoPhase[]` 선택 필드. leg-curl에
   `[수축1, 정지1, 이완2]`.
2. 가이드는 `catalog.tempo ?? TEMPO[group]` — 갈림은 한 곳(가이드가 phases를 얻는
   자리)에서만. `cycleSeconds`·`tempoPositionAt`은 phases 배열을 받으므로 그대로 동작.
3. 시드 변경이므로 **seedRevision 갱신 + 해시 쌍** (관례), 기존 설치 DB는 seedRepair
   경로 확인.

**검증**: leg-curl 사이클이 4초(1+1+2)라는 이름 붙은 테스트 + 오버라이드 없는 종목이
그룹 템포를 그대로 받는 테스트.

## CC6. 휴식 −30초 버튼

**피드백**: "+30초는 있는데 −30초는 없음."

**설계**: RestTimerBar 버튼 행을 `[−30초][+30초][건너뛰기]`로.
`addSeconds(-30)`이 동작하도록 `extendEndTime` 옆에 감산 규칙을 정의한다:
`endTime = max(now, endTime − 30s)`, `totalSec = max(0, totalSec − 30)`.
남은 시간이 30초 미만일 때 누르면 0이 되어 **정상 종료 플로우**(차임 + 자동 닫힘)를
탄다 — 건너뛰기와 같은 결과이고, 그게 맞는 의미다.

**검증**: 감산 클램프 단위 테스트 (경계: 남은 5초에서 −30 → 즉시 종료 · 음수 totalSec
없음). 진행 바 폭이 3버튼에서 375px 한 줄에 들어가는지 실측 (X8 부류).

## CC7. 템포 사운드를 연속 글라이드로 — "화면을 안 봐도 따라가게"

**피드백**: "매 틱이 아니라 도로로로 올라갔다 내려오는 느낌 (애플워치 명상처럼).
지금은 이완하다 갑자기 수축 사운드가 들리면 반 박자 늦고 호흡도 꼬인다."

**핵심 통찰 — 지금 구조의 한계**: 페이즈 **경계**에서 한 번 울리는 소리는 "방금
바뀌었다"만 말하고 "언제 바뀔지"를 말하지 못한다. 반 박자 늦는 것은 사용자 잘못이
아니라 신호 설계의 귀결이다. 연속 글라이드는 **피치의 진행 방향과 위치**가 곧
남은 시간이라, 예측이 소리 안에 들어 있다.

**설계** — `phaseTone`(단발)을 `phaseGlide`(페이즈 길이만큼 지속)로 교체:

1. 페이즈 경계마다(기존 effect 자리) 그 페이즈 길이의 oscillator 하나를 예약:
   - **수축(1초)**: 392→659Hz 상행 램프 (`frequency.linearRampToValueAtTime`)
   - **정점 짜내기(1초)**: 659Hz 유지
   - **이완(2~3초)**: 659→392Hz 하행 램프 (페이즈 길이에 맞춰)
   - **신장 정지(1초)**: 392Hz 유지, 게인 한 단 낮게 (쉼의 신호)
2. 게인 엔벨로프: 어택 30ms · 서스테인 (기본 0.14 × volumeScale) · 릴리즈 30ms —
   페이즈 간 이음새에서 클릭이 없어야 한다. 전부 `tone()`과 같은 초크포인트 계열로,
   태그 `'tempo'` (CC2 취소 대상).
3. **유지하는 것**: 카운트인 틱, 마지막 사이클 큐(고음 더블), 휴식 차임 — W2에서
   설계한 "형태로 구분" 자산. 글라이드는 그 사이를 채우는 연속층이다.
4. 주파수 대역 392~659Hz는 W2 분석의 스피커 유효 대역 안이다. 음악과 섞여도(ambient)
   존재감이 유지되도록 CC8의 게인 상향과 함께 실기기 청감으로 조정한다.
5. 화면 잠금 복귀 시: 파생 타이밍(`tempoPositionAt`)이 현재 페이즈를 주므로 그
   페이즈의 글라이드를 중간부터가 아니라 **다음 경계부터** 재개 (현행 톤과 같은 규칙).

**검증**: 글라이드 스펙(시작·끝 주파수, 지속) 단위 테스트 + 클릭 없음·청감은 실기기.
자동 종료 시 글라이드가 차임과 겹치지 않게 `cancelTag('tempo')` 후 차임 (순서 테스트).

## CC8. 소리 실출력 상향 — 설정은 이미 '최대'다

**피드백**: "템포가이드랑 휴식시간 사운드 아직도 너무 작음."

**확인된 사실**: 백업의 `soundVolume = max` — **단계를 더 만드는 것은 답이 아니다.**
W2 분석대로 주파수·길이는 이미 유효 대역이므로, 남은 것은 게인 헤드룸이다.

**설계**:

1. 기본 게인 상향: TICK 0.2→**0.3** · CHIME 0.26→**0.36** · LAST_CYCLE 0.22→**0.3**
   (글라이드는 신설값 0.14 기준). 배율표 재정의: normal **1.0** / loud **1.5** /
   max **2.2** — max 실효: 차임 0.79, 틱 0.66 (사인파, per-tone 1.0 클램프 유지 —
   클리핑 없음).
2. **지각 음량 보강 (구현 재량)**: 각 톤에 옥타브 하모닉(freq×2, 게인 0.4배)을 겹치면
   같은 피크에서 더 크게 들린다 — 시도해 보고 실기기에서 판단, 채택 여부를 DEV-RECORD에.
3. 미리 듣기(설정)는 그대로 — 새 게인·글라이드가 거기서도 들려야 한다.

**검증**: 게인 스펙 테스트 갱신 + 실기기: 음악 튼 채로 max에서 틱·차임·글라이드 3종.

## CC10. 맨몸 종목에 "무게 미입력" 오탐 (리뷰어 발견 — 오늘 실데이터)

**근거**: 오늘 백업에서 크런치 `weight: 0`으로 3세트 체크 — **맨몸 수행이 정상인
종목인데 BB6 힌트("무게 미입력")가 떴을 상태다.** 데드버그도 같은 부류이고, 데드버그는
애초에 무게를 얹을 수 없다.

**설계**: `Exercise`에 `allowZeroWeight?: true` (crunch, dead-bug).
`zeroWeightHint`가 inverse에 더해 이 플래그도 제외한다 — 판정 함수 시그니처에 플래그를
추가하고 갈림은 그 함수 안에서만. 증량 제안이 맨몸 크런치에 "+2.5kg"를 내는 문제는
**이번에 다루지 않는다** (케이블 크런치로 부하를 얹으라는 조언으로 읽어도 틀리지 않다 —
관찰만 기록).

**검증**: crunch 0kg 체크 → 힌트 없음 (이름 붙은 테스트: "맨몸 크런치는 무게 미입력이
아니다"), 일반 종목 0kg → 힌트 유지.

## CC11. 진행 중 세션이 있으면 홈 카드가 그 세션을 보여준다

**피드백**: "운동 중에 홈으로 나오면 카드가 지금 하는 운동으로, 시작 버튼이 '이어서
하기'로 바뀌면 좋겠다. 실수로 누르면 세션이 날아갈까 불안하다."

**확인된 현재 동작**: 열린 세션이 있어도 카드는 **다음 제안 Day**를 보여주고 버튼도
"{제안} 시작"이다. 다만 **데이터는 이미 안전하다** — `start()`가 열린 세션을 감지하면
`OpenSessionSheet`(이어서 / 마치고 시작 / 버리고 시작)를 먼저 띄우고, `store.begin`도
덮어쓰기를 거부한다. 불안은 실재하지만 유실 경로는 없다 — 고칠 것은 **화면이 그 사실을
말하지 않는 것**이다.

**설계**:

1. `openSession`이 있으면 카드가 **세션 모드**로: Day 이름 + "진행 중 · N분 · 완료
   k/m세트". 제안 이유 자리는 "진행 중인 세션이 있어요".
2. primary 버튼 → **"이어서 하기"** (`onEnterSession()`). [변경]은 유지 — 다른 Day로
   갈아타는 경로이고, 그쪽은 기존 OpenSessionSheet 가드가 그대로 받는다.
3. 하단 재개 스트립은 유지 (다른 탭 커버). 홈에서 같은 정보가 카드+스트립 두 번 뜨는
   것은 허용 — 카드가 주 시선이고 스트립은 위치 고정 앵커다. (v1.6에서 홈 배너를
   스트립으로 통합한 것과 반대 방향이 아니냐는 의문에 대해: 그때 지운 것은 **같은 줄글
   배너**였고, 이번 것은 주 행동 버튼의 라벨 정확성이다.)

**검증**: 카드 모드 파생 순수 함수 + 소스 스캔 (카드가 openSession을 본다).

## CC12. 스테퍼를 "뗄 때 1스텝"으로 — 롱프레스 가속 제거

**피드백**: "− + 에 손을 올리고만 있어도 쭉 올라간다. 드래그해도 바뀐다. 손 뗐을 때만
반응해야 할 것 같다. 오터치 복구가 귀찮다."

**확인된 현재 동작**: 의도된 설계다 — `NumberStepper`가 **롱프레스 가속 반복**
(400ms 후 110ms 간격, 8회 후 55ms 가속, DESIGN §5.2)을 구현하고 있다. 설계 가정은
"큰 점프를 빠르게"였는데, 실사용 환경(땀, 장갑, 기구 사이 이동 중 오터치)에서는
**가속이 오터치를 증폭하는 장치**가 된다. 실사용이 설계 가정을 이겼다.

**설계**:

1. 발화 시점을 **pointerup**으로: 버튼 안에서 떼고, 이동 슬롭 12px 이내일 때만 1스텝.
   pointercancel·슬롭 초과·버튼 밖 릴리즈 = 무발화 (표준 탭 판정).
2. **롱프레스 반복·가속 전부 제거** (HOLD_DELAY/REPEAT/ACCEL 상수와 타이머 삭제).
   큰 점프는 직접 입력(가운데 필드)이 이미 담당한다 — 반복이 없어도 경로가 있다.
3. 시각 피드백: pointerdown에 pressed 스타일 (뗄 때 반응이라는 것이 눌림으로 보여야
   한다). DESIGN.md §5.2의 "롱프레스 가속 스테퍼" 문구를 이 결정으로 갱신.

**검증**: 탭 판정 순수 함수 (슬롭·경계) + 반복 타이머 부재 소스 스캔. 실기기: 꾹 눌러도
1스텝, 드래그 스크롤 중 스쳐도 무발화.

## CC13. 첫 기록 종목의 시작 무게 추정 프리필

**피드백**: "기준 기록 없는 운동은 신체 조건으로 추정한 권장 시작 무게가 입력돼 있으면
좋겠다. 안 맞으면 그날 조절할게."

**설계** — substitute.ts의 기존 원칙(휴리스틱 시작점 + 캘리브레이션이 본체)을 첫 기록으로 확장:

1. catalog `Exercise`에 `startWeightPctBW?: number` — **체중 대비 비율, 미검증 코칭
   휴리스틱임을 주석에 명시** (`startFactor`와 같은 표기 수준). 골격근량 입력은 받지
   않는다 — 머신 브랜드 편차가 계수 정밀도를 무의미하게 만들고, 본체는 어차피 첫 세트
   RIR 3~4 캘리브레이션이다.
2. `prefill`: 해당 recordKey 기록이 없고 계수가 있으면
   `weight = roundToScale(bodyWeightKg × pct)` (그 종목의 무게 단위·사다리로 반올림),
   고스트 텍스트 **"추정 시작 무게 — 첫 세트에서 조절"**. 체중 미입력이면 현행(0) 유지.
3. 값 선정 규칙: **실제보다 가볍게** — 남는 것(올리기)이 부족한 것(내리고 자존심 상하기)
   보다 낫고, 문서 강도 진단 절차와도 맞는다. 구현이 종목별 값을 채우고 DEV-RECORD에
   표로 기재. 어시스티드(inverse)는 기존 보조 무게 역산 로직 재사용.

**검증**: 계수 프리필 단위 테스트 (반올림·체중 없음 폴백·기록 있으면 미적용) +
"기록이 하나라도 생기면 추정이 다시는 안 나온다" 이름 붙은 테스트.

## CC14. 종목별 메모 이력 — 새 저장소 없이 파생

**피드백**: "운동마다 메모를 남긴 날과 내용이 이력으로 남으면 좋겠다."

**확인된 현재 동작**: **데이터는 이미 쌓이고 있다.** 세션 entry의 감각 메모
(`sensoryNote`)가 날짜(세션)와 함께 저장된다 — 없는 것은 그것을 **이력으로 보여주는
화면**뿐이다. 머신 세팅 메모(exerciseNotes)는 성격이 다르다 (현재값 1개 — "시트 3칸"은
이력이 아니라 상태).

**설계** (스키마 불변 — 파생 원칙):

1. **ExerciseCard에 직전 메모 노출**: 그 recordKey의 최근 세션에 sensoryNote가 있으면
   감각 메모 입력칸 위에 "지난번({날짜}): {메모}" 한 줄 — LLM 내보내기로 돌아오던
   피드백 루프('리어델트 목 긴장' 같은 것)가 **다음 세션 현장에서 바로** 보인다.
2. **종목 히스토리 화면에 메모 타임라인**: 그 종목의 세션들에서 sensoryNote·
   보상작용('없음' 제외)을 날짜순으로 — 저장은 이미 있으니 읽기만 추가한다.
3. 세션과 무관한 메모가 필요하면 머신 세팅 메모가 그 자리다 (현행 유지).

**검증**: 타임라인 파생 함수 단위 테스트 (없는 메모 생략·날짜순) + 소스 스캔.

## CC15. 자유 종목 추가 — "머신이 다 차 있을 때"

**피드백**: "그 Day 머신이 다 차 있으면 루틴의 다른 운동이라도 가볍게 하고 싶다.
기록도 남아야 하고, 주간 볼륨 반영을 어떻게 할지 고민."

**설계**:

1. 세션 화면 하단 "+ 종목 추가" → 시트: **루틴 전체 종목** (전 Day, 현재 세션에 있는
   것 제외), Day별 그룹핑. 대체(T8)와 다른 경로다 — 대체는 "이 종목 대신", 이것은 "얹기".
2. 추가된 entry의 recordKey는 **원소속 Day의 라인** (`pec-deck@d1`처럼) — 기록 라인
   연속성 원칙 그대로라 프리필·PR·증량 판단이 그 종목의 본 라인에 이어진다.
   `SessionEntry`에 `extra?: true` (persist 추가 필드 — 백업 하위호환은 additive라 안전,
   스키마 검토 한 줄 기재). 카드에 "추가" 칩, 내보내기에 표기.
3. **주간 볼륨 반영 — 정상 산입한다.** 실제로 수행한 자극이고, 제안 점수·회복 감쇠도
   사실 기반이어야 한다. "몸 풀기 수준이라 빼고 싶다"는 경우는 **기존 워밍업 토글**이
   이미 세트 단위로 그 일을 한다 — 새 규칙을 만들지 않는다 (`doneSets` 초크포인트가
   자동으로 처리). 이 판단을 계획서 답으로 명시: 반영 방식은 "자동 절반 계상" 같은
   마법값이 아니라 **사용자가 세트에 붙이는 사실(워밍업 여부)**로 갈린다.
4. 세트 수 기본값은 그 종목의 원 Day 정의 — 기존 +세트/−세트로 조절.
5. `routineExerciseOfEntry`가 다른 Day의 recordKey를 세션 안에서 올바르게 해석하는지
   확인 (초크포인트라 될 것이나, 이름 붙은 테스트로 고정).

**검증**: 추가 entry의 볼륨·제안 산입 테스트 + extra 백업 왕복(내보내기→복원) 테스트.

실측에서 결함 하나를 찾아 고쳤다 (§3.1): **얹은 종목(CC15)이 프리필을 못 받고 있었다** —
다른 Day의 recordKey라 `prefills` 맵에서 빠져 추정 무게도 지난 기록도 화면에 닿지 않았다.
같은 자리에서 **대체 수행(T8)은 여전히 비어 있고**, 그쪽은 `firstExposure` 판정이 걸려 있어
건드리지 않았다 — 질의 5.

소급 효과 (§7): 내전근 목표 신설로 **D3 점수 5.55 → 6.45**, 세트 14 → 17, 볼륨 바 9개 부위.
