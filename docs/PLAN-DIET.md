# 식단 기록 설계 (D1~D5) — 2026-08-01

> 사용자 요구로 DESIGN.md §1 비목적("식단 기록 없음")을 **공식 철회**한다.
> 구현 순서: **FINISH-LINE R1~R5를 먼저 끝내고 이 라운드를 시작할 것.**
> 원칙 유지: 입력 마찰 최소화 / 원데이터는 앱, 깊은 판단은 LLM 내보내기 / 파생값 비저장.

## 0. 설계 판단 (사용자 위임분 — 근거 포함, 임의 변경 금지)

1. **플랜 전환은 일 단위 + 벌크 액션.** 주 단위 전환은 제공하지 않는다 — 회식은 날짜 단위
   사건이고, 주 단위 스위치는 "이번 주는 망함" 프레임을 만든다 (과거 붕괴의 심리 패턴).
2. **연속 저칼로리 가드.** 1,500대가 연속 3일을 넘으면 경고 배너. 근거: 루틴 문서 15장
   "전날 초과분을 만회하려고 덜 먹지 않는다" — 구조화된 소폭 보정(−250, 단백질 보존)은
   허용하되, 장기화는 문서가 금지한 만회성 절식이다. 배너 문구에 이 근거를 그대로 쓴다.
3. **앱은 음식의 좋고 나쁨을 판단하지 않는다.** 대체 기록에 자가 태그 3단만 받고,
   실질 판단은 내보내기 → LLM 분석 경로. 음식 DB·칼로리 검색은 v2에서도 하지 않는다
   (과설계 + 입력 마찰).
4. **캘린더는 운동과 통합.** 기존 기록 탭 달력 셀에 불꽃(운동) + 테두리 링(식단 준수).
   식단 전용 달력을 만들지 않는다.
5. **훈련일/휴식일 슬롯 자동 전환 + 수동 토글.** 기본은 훈련일 구성(6슬롯), 오늘 완료
   세션이 없고 사용자가 토글하면 휴식일 구성(5슬롯 — 훈련 전후를 15시 블록으로 통합,
   루틴 문서 15장 규칙 그대로).

## 1. 데이터 모델 (Dexie v3)

```ts
interface DietPlan {
  id: string                    // "cut-1800" | "cut-1500"
  name: string                  // "감량 1,800" | "보정 1,500"
  kcalLabel: string             // "약 1,796kcal · 단 166g"
  isDefault?: boolean
  slots: DietSlot[]             // 훈련일 구성
  restDaySlots: DietSlot[]      // 휴식일 구성
  seedRevision: number          // R2와 같은 규칙 (해시 스냅샷 테스트 포함)
}

interface DietSlot {
  id: string                    // "breakfast" | "lunch" | "afternoon" | "pre" | "post" | "dinner"
  name: string                  // "아침" | ... | "훈련 전" | "훈련 직후"
  timeHint: string              // "07:30"
  items: DietItem[]
}

interface DietItem {
  id: string                    // "brown-rice"
  name: string                  // "현미밥 150g"
  qty: string                   // "1개" | "2팩"
  kcal: number
  proteinG: number              // 단백질 합계 표시용 (§4)
}

/** 하루 기록. date가 PK — 하루 하나 */
interface DietDay {
  date: string                  // "2026-08-04"
  planId: string
  isTrainingDay: boolean
  slots: Record<string, SlotRecord>   // slotId → 기록. 손 안 댄 슬롯은 키 없음
  note?: string
}

interface SlotRecord {
  checkedItemIds: string[]
  /** 슬롯 전체/일부를 다른 음식으로 대체한 경우 */
  substitution?: {
    text: string                       // "회사 근처 서브웨이 15cm 터키"
    quality: 'similar' | 'other' | 'cheat'
    // similar = 단백질원 있음 + 튀김/설탕 위주 아님 (기준을 입력 시트에 명시)
    // other   = 그냥 다른 음식
    // cheat   = 치팅인 걸 알고 먹음
  }
  skipped?: boolean                    // 그 끼니 자체를 안 먹음
}

// Settings 추가: defaultDietPlanId: string
// dailyPlanOverride는 DietDay.planId가 담당 (별도 테이블 불요)
```

- Dexie version(3): `dietDays` 테이블 (`&date`). 플랜은 시드 JSON → `dietPlans` 테이블
- JSON 백업·Gist에 dietDays·플랜 포함. 백업 SCHEMA_VERSION **상향** (새 테이블 = 구버전
  앱이 이해 못 하는 파괴적 변경 — REVIEW-REQUEST 2-2에서 합의한 원칙의 적용 사례)

## 2. 시드 — 두 플랜 (루틴 문서 15장 기준)

**cut-1800 (기본)**: 문서 15장 끼니 배치 그대로.

| 슬롯 | 항목 (kcal / 단백질g) |
|---|---|
| 아침 07:30 | 반숙란 3개 (225/20) · 멀티비타민 1정 (0/0) · 오메가3 1캡슐 (10/0) |
| 점심 11:30 | 현미밥 1개 (215/4) · 닭가슴살 2팩 (180/34) · 채소 (0/0) · 올리브오일 1큰술 (115/0) |
| 오후 15:00 | 아몬드 25g (145/5) |
| 훈련 전 17:30 | WPI 1스쿱 (93/23) · 바나나 1개 (105/1) |
| 훈련 직후 20:00 | WPI 1스쿱 (93/23) · 바나나 1개 (105/1) |
| 저녁 21:00 | 현미밥 1개 (215/4) · 닭가슴살 3팩 (270/51) · 채소 · 멀티 1정 · 오메가3 1캡슐 (10/0) |

합계 ≈ 1,796kcal / 단백질 166g. **휴식일 구성**: 훈련 전·직후 슬롯을 "오후 15:00~16:00"
하나로 통합 (WPI 2스쿱 + 바나나 2개), 총량 동일 — 문서 15장 규칙.

**cut-1500 (보정)**: cut-1800에서 **저녁 현미밥 1개만 제외.** 합계 ≈ 1,581kcal / 단백질 166g /
지방 53g(하한 50g 위) / 훈련 전후 탄수 96g 보존. "외울 것: 보정일 = 저녁 밥만 뺀다."

라벨·수치는 사용자가 실제 제품 라벨로 보정할 수 있게 플랜 JSON 가져오기/내보내기 지원
(운동 루틴과 같은 경로 — RoutineIoPanel 패턴 재사용).

## 3. 화면 — 식단 탭 (탭바 5번째)

### 오늘 화면 (기본)

```
[감량 1,800 ▾]  [훈련일 ⇄]        단백질 112/166g · 1,240kcal
┌ 아침 07:30 ────────────── ● ┐
│ ☑ 반숙란 3개  ☑ 멀티  ☑ 오메가3 │
├ 점심 11:30 ────────────── ◐ ┤
│ ☑ 현미밥  ☐ 닭가슴살 2팩  ☑ 오일 │
│ [일부 대체] "구내식당 제육" · 비슷한 구성 │
├ 훈련 전 17:30 ──────────── ○ ┤
│ ☐ WPI  ☐ 바나나                │
└ ... ─────────────────────────┘
```

- 항목 탭 = 체크 토글, **즉시 저장** (운동 세션과 같은 write-through)
- 슬롯 헤더의 […] → 시트: [전부 먹음(일괄 체크)] [대체했어요] [스킵]
  - "대체했어요" → 텍스트 입력 + 품질 3버튼 (기준 문구 표시:
    "단백질원이 있었고 튀김·설탕 위주가 아니면 '비슷한 구성'")
  - 일부 체크 + 대체 입력 = 일부 대체 (별도 상태 불요 — 데이터가 표현함)
- 상단: 플랜 전환 시트 — [오늘만 1,500] [내일부터 N일] (N=1~3), 연속 4일째부터 경고 배너
- 훈련일 ⇄ 휴식일 토글: 오늘 완료 세션이 생기면 자동으로 훈련일 고정
- **단백질 진행 숫자**가 이 화면의 핵심 지표 (§4) — 칼로리는 보조 표기

### 과거 날짜

기록 탭 달력에서 날짜 탭 → 세션 상세 아래 식단 요약 + 편집 (당일 입력 누락 보정)

## 4. 파생 계산 (저장하지 않음)

```
슬롯 점수: full(전부 체크) = 1 / substitution.similar = 1
          부분 체크(≥절반) 또는 substitution.other = 0.5
          부분 체크(<절반) = 0.25 / substitution.cheat = 0 / skipped = 0.5
          (skipped 0.5 근거: 감량 문맥에서 덜 먹은 것은 실패가 아니다. 단 단백질 손실은
           단백질 지표가 따로 잡는다)
하루 준수: 기록된 슬롯 점수 평균. 슬롯 3개 미만 기록이면 "미기록" (판정 안 함)
  ● ≥0.85 / ◐ ≥0.5 / ○ <0.5
단백질 추정: Σ(체크 항목 proteinG) + similar 대체는 그 슬롯 계획 단백질로 인정,
  other/cheat는 0으로 (라벨: "추정")
연속 1,500 카운트: DietDay.planId 연속일 수 → 4일째부터 배너
```

### 캘린더 통합 (기록 탭)

셀 = 불꽃(운동, 기존) + **테두리 링 색**(식단: ●초록 ◐주황 ○빨강, 미기록은 링 없음).
월 요약에 "식단 준수 18/24일" 추가.

## 5. 내보내기 (LLM 분석 경로 — 필수)

MD 내보내기에 일자별 식단 섹션 추가:

```markdown
### 식단 — 감량 1,800 · 훈련일 · 준수 ◐ (단백질 추정 142g)
- 아침 ●  점심 ◐ (닭가슴살 미섭취, 일부 대체: "구내식당 제육" — 비슷한 구성)
- 훈련 전 ○ 스킵
- 저녁 ✗ 대체: "떡볶이+튀김" — 치팅
```

대체 텍스트가 그대로 실려야 LLM이 패턴("회식 다음 날 아침 스킵이 반복" 등)을 잡는다.
운동 섹션과 같은 날짜 아래 붙인다 — 훈련 품질과 전날 식단의 상관을 볼 수 있게.

## 7. 하지 않는 것

- 음식 DB / 칼로리 검색 / 사진 인식 — 과설계, 마찰 증가
- 자유 식단 작성기 — 플랜은 JSON 시드/IO로 충분 (루틴과 동일 사상)
- 체중 기록 — 여전히 비목적 (인바디 앱)
- 식사 알림 — T6 조사 결론 그대로 (플랫폼 제약)
