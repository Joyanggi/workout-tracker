# 1. 미해결 — 확인된 결함

## 1.1 [높음] `inverseWeight`가 증량 판정에만 적용돼 있다

**배경.** T8에서 어시스티드 풀업(`assisted-pullup`)을 추가했다. 이 머신은 표시 무게가
**보조 무게**라서 클수록 쉽다. 진전은 숫자가 **줄어드는** 것이다.
`Exercise.inverseWeight: true`로 표시하고 `weightScale.nextWeightForProgression`에서
증량 방향을 뒤집었다.

**문제.** 그 플래그를 참조하는 곳이 `progression.ts`와 `weightScale.ts` 둘뿐이다.
다음 경로는 전부 방향이 뒤집힌 상태로 남아 있다:

| 위치 | 현재 동작 | 결과 |
|---|---|---|
| `lib/pr.ts` `detectPrs` | `topWeight > prev.weight` | **보조를 늘리면(더 쉬워지면) "최고 무게 PR"이 뜬다.** 보조를 줄인 실제 진전은 PR로 잡히지 않는다 |
| `lib/pr.ts` e1RM PR | `e1rm(weight, reps)` 최대 | 같은 방향으로 뒤집힘 — 거짓 PR |
| `lib/derive.ts` `totalVolume` | `Σ weight × reps` | 보조를 많이 받을수록 "볼륨"이 커진다 |
| `lib/analysis.ts` `strengthTrend` | 최고 세트 = e1RM 최대 | 가장 많이 보조받은 세트를 "최고 세트"로 고른다. topLoad·volume·e1rm 추이 전부 뒤집힘 |
| `lib/prefill.ts` `better()` | 무게 큰 쪽을 채택 | 최근 3세션 중 **가장 많이 보조받은** 세션이 프리필 기준이 된다 → 쉬워지는 방향으로 고착 |
| `components/CompensationWatchSheet` | `stepDown`으로 "한 단위 하향" | 어시스티드에서는 보조를 줄여 **더 어렵게** 만든다 |

거짓 PR이 특히 나쁘다 — PR은 사용자가 기뻐하는 신호이고, 한 번 거짓이면 신뢰가 깨진다.
T7에서 워밍업이 반복 PR로 잡히지 않게 회귀 테스트를 박은 것과 같은 이유다.

**도달 경로 (노출 범위).** `assisted-pullup`은 카탈로그에 있지만 루틴에는 없다.
유일한 경로는 T8 대체다 — `lat-pulldown@d2`(**그룹 A**, 8~12회) 자리가 없을 때
사용자가 선택하면 `assisted-pullup@d2`로 기록된다. 즉 대체를 쓰지 않으면 발생하지 않지만,
쓰는 순간 A그룹 분석 경로 전체가 영향받는다.

**판단이 필요한 지점.** 넷 중 무엇을 택할지가 리뷰 요청 사항이다:

- **(a) 전 경로에 inverse를 전달한다** — `catalog`(또는 inverse 판정자)를 `derive`·`pr`·
  `analysis`·`prefill`까지 넘긴다. 정확하지만 배관이 넓어지고, 순수 함수들이 카탈로그를
  알게 된다 (지금은 루틴만 안다)
- **(b) 기록값을 "실효 부하"로 바꾼다** — `체중 − 보조`를 저장하면 하위 계산이 전부
  그대로 맞는다. 대신 **화면 숫자가 머신 핀과 달라져** "머신 한 핀" 전제(루틴 문서 10장,
  T9 전체)가 깨진다. 기록 시점에 체중이 필요하다
- **(c) inverse 종목을 PR·볼륨·추이 분석에서 제외한다** — 반복수 진전과 감각만 보여주고
  "보조 무게는 줄어드는 것이 진전"이라는 안내를 붙인다. 값이 싸고 **틀린 숫자를 없앤다.**
  대신 진전 가시화가 약해진다
- **(d) `assisted-pullup`을 대체 후보에서 뺀다** — 계획서도 이 항목만 startFactor 없이
  "특수"로 표시했다. 기능을 잃지만 결함도 사라진다

**내 권고: (c).** v1.1 범위에서 조용히 틀린 숫자를 없애는 것이 가장 시급하고,
(a)는 순수 함수의 의존성을 넓히는 대가가 크다. (b)는 v1.2에서 "체중 기반 종목"을
제대로 다룰 때 함께 볼 문제로 남긴다. **다만 이건 운동학·UX 판단이 섞여 있어
동의를 받고 싶다.**

## 1.2 [중간] 수정 이전에 만들어진 백업 파일은 여전히 복원되지 않는다

`063f0ad`은 **저장된 루틴**을 고친다. 그 이전에 내보낸 JSON/Gist 백업은 파일 안의
루틴에 `fallbackDays[].recordDayId`가 없어서 `parseBackup`의 `validateRoutine`이 거부한다.

- 현재 알려진 노출: 없음 (사용자 계정에 workout-tracker gist가 없었고, 검증용으로 만든
  것은 삭제했다). 사용자가 따로 내려둔 JSON 파일이 있으면 복원 불가
- 선택지: ① 그대로 둔다(노출 없음) ② 복원 시 `recordDayId`가 없고 `fallbackDays`의
  id가 번들과 일치하면 번들 값으로 보정한다 ③ 검증을 경고로 낮춘다(권장하지 않음 —
  검증이 실제 데이터 오염을 잡는 장치다)

## 1.3 [낮음] 루틴 `version`이 내용 변경을 따라가지 않는다

이번 P0의 근인이다. `recordDayId`를 마일스톤 2에서 시드 JSON에 추가했는데
`version`은 마일스톤 1 이후 계속 `2.4`였고, `ensureSeed`가 version만 보고 재주입을
판단해서 낡은 복사본이 영구히 남았다.

`063f0ad`은 "정합성 검사를 통과하지 못하면 되돌린다"로 **증상 재발을 막는다.** 그러나
**번들 내용이 바뀌었는데 검사를 통과하는 변경**(예: cueTip 문구 수정, muscleSets 숫자 조정)은
여전히 기존 설치본에 전달되지 않는다. 카탈로그는 매 부팅 `bulkPut`이라 괜찮고, 루틴만 문제다.

판단 필요: version을 올릴 규칙을 두는가(예: 시드 JSON 변경 시 필수), 아니면 루틴도
"사용자가 가져온 적 없으면 매 부팅 갱신"으로 바꾸는가.

## 1.4 [낮음] 세션 테이블 전체 조회

홈·기록·분석이 `db.sessions.toArray()`를 쓴다. 수백 건까지는 문제없다고 판단했으나
근거는 측정이 아니라 추정이다. `date` 인덱스 범위 쿼리로 좁힐 지점이 어디인지 검토 요청.

# 2. 검토해 주면 좋은 판단 (이미 내렸지만 확신이 낮은 것)

각 항목은 코드 주석과 커밋 메시지에 근거가 있다. **뒤집을 이유가 있으면 알려주면 좋겠다.**

1. **`exerciseNotes` 테이블 이름을 유지했다** (T9) — 행에 무게 단위가 들어갔으니
   `exerciseSettings`가 맞지만, T4가 이미 스키마 v2로 배포돼 이름 변경은 2단계
   마이그레이션으로 실제 기록을 옮겨야 한다. 얻는 것이 이름뿐이라 보류했다
2. **T9에서 백업 `SCHEMA_VERSION`을 올리지 않았다** — 같은 행에 필드를 더한 것이고
   복원은 행을 통째로 put하므로 구버전 앱도 값을 잃지 않는다. 올리면 오히려 그 앱이
   파일을 거부한다. "버전은 항상 올리는 게 안전"의 반례라고 판단했다
3. **사다리 ± 이동을 "스냅 후 이동"이 아니라 이웃 핀 직행으로 했다** (T9) —
   `[35, 41]`에서 36에 있을 때 스냅(35) 후 하강이 30으로 가서 35를 잃는다
4. **환산 계수와 실측 보정을 다른 함수로 분리했다** (T8) — `startWeightFor`(휴리스틱)와
   `calibratedWeight`(Epley 역산). 주석에 "검증 안 됨"을 쓰는 것보다 함수를 쪼개서
   호출부가 어느 쪽을 쓰는지 드러나게 하는 편이 낫다고 판단했다
5. **B그룹에서 "제안"과 "절대 기준"을 다르게 처리했다** (T10) — 회복 힌트는 프리필을
   바꾸지 않고, 감각 1점 복귀는 프리필을 자동으로 내린다. 루틴 문서가 후자만
   "절대 기준"이라고 규정하기 때문
6. **반복 보상작용 판정 창을 "그 종목을 수행한 세션" 기준으로 했다** (T11) — 달력상
   최근 3세션으로 세면 "3세션 중 2회"가 실제로는 "6주 중 2회"가 된다
7. **대체 수행의 부위 집계는 원 종목을 따라간다** (T8, `routineExerciseOfEntry`) —
   기록 라인(`recordKey`)만 분리하고 계획(그룹·목표 반복수·부위)은 원 종목을 되짚는다
8. **`Settings.bodyWeightKg`를 추가했다** (T8) — 어시스티드 보조 무게 역산 전용.
   체중 **추이**는 저장하지 않는다(설계상 비목적). 필드 하나를 둔 것이 맞는지
