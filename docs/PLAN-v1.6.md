## AA1. Day 선택이 시작을 겸하지 않게 — 선택과 시작의 분리

**피드백**: "추천 Day 말고 다른 Day를 카드에서 고르면 시작 버튼 없이 바로 시작된다.
고른 Day를 시작 버튼으로 시작하고 싶다."

**확인된 현재 동작**: `DayPickerSheet.onPick → start(day)` (HomeScreen 479행) —
시트에서 행을 탭하는 순간 세션이 만들어지고 화면이 전환된다. 하한 모드 행도 같다.
DESIGN.md §4의 원문("탭하면 선택 시트가 열림")이 '선택=시작'을 명시한 적은 없는데
구현이 그렇게 굳었다.

**왜 고쳐야 하나**: 제안 Day는 **보고 나서 시작**하는 2단인데(카드 → 시작 버튼),
다른 Day는 **보는 행위가 곧 시작**인 1단이다. 같은 결정(오늘 뭘 할까)의 무게가 경로에
따라 달라지고, 둘러보기(각 Day의 종목·세트 수 비교)가 불가능하다 — 잘못 탭하면
세션이 생겨 버려서, 버리거나 강제 기록해야 한다 (Z5에서 사용자가 겪은 것과 같은 부류).

**설계**:

1. HomeScreen에 `pickedDayId: string | null` 상태 하나. `onPick`은 **선택만 바꾸고
   시트를 닫는다** — 세션을 만들지 않는다.
2. 카드와 시작 버튼이 `displayDay = picked ?? suggestion.day`를 쓴다.
   - 직접 선택 상태의 카드: 제안 이유 자리에 **"직접 선택 — 제안은 {제안 Day 이름}"**을
     보여준다 (제안이 무시된 게 아니라 보류된 것임을 화면이 말해야 한다).
   - 시트에서 **제안 Day를 다시 고르면 override를 지운다** (pickedDayId = null) —
     "제안으로 되돌리기"를 별도 행으로 만들지 않는다.
3. 시작 버튼 라벨은 지금처럼 `{displayDay.name} 시작`. `start()`는 시작 시
   pickedDayId를 지운다.
4. 선택 상태는 **컴포넌트 상태로 둔다** (저장하지 않는다). 탭을 옮겼다 돌아오면
   제안으로 돌아가는데, 그게 맞는 방향이다 — 다음 날 열었을 때 어제의 수동 선택이
   남아 있는 것이 더 나쁜 실패다 (파생값 비저장 원칙과 같은 결).
5. 디로드 배너의 "디로드로 시작"은 그대로 즉시 시작한다 — 그 버튼은 라벨이 이미
   "시작"이므로 1단이 맞다. `pending`(진행 중 세션 처리) 경로는 `start()` 안에 있어
   자동으로 같이 동작한다.

**테스트**: onPick이 세션을 만들지 않는다 · displayDay 파생 · 제안 재선택 시 override
해제 · 시작 후 초기화.

**문서**: repo `docs/DESIGN.md` §4의 해당 문장을 "시트는 선택만 바꾸고, 시작은 항상
시작 버튼"으로 갱신한다 (DayPickerSheet 상단 주석의 인용도 같이).

## AA2. "다른 Day 선택"을 보이는 버튼으로

**피드백**: "카드를 눌러 바꿀 수 있다는 걸 실사용자가 직관적으로 알 수 없다."

**확인된 현재 동작**: 카드 하단에 텍스트 힌트 "탭해서 다른 Day 선택 ▸" (364행)가
있지만, 카드 전체가 버튼이라는 사실은 시각적으로 드러나지 않는다 — 사용자 본인이
힌트를 읽고도 확신을 못 했다는 것이 이 피드백이다. 힌트는 **읽는 사람**에게만 보이고,
버튼은 **훑는 사람**에게도 보인다.

**설계**:

1. 시작 버튼을 버튼 행으로 바꾼다: **`[{displayDay.name} 시작] (primary, 넓게) ·
   [변경] (secondary)`**. "변경"이 DayPickerSheet를 연다 — 명시적이고, AA1의 선택
   모델과 정확히 짝이 맞는다 (변경 → 고르기 → 시작).
2. 카드 탭으로 시트가 열리는 기존 경로는 **유지한다** (아는 사람의 지름길). 다만
   하단 힌트 문구는 제거한다 — 보이는 버튼이 생겼으므로 텍스트 힌트는 중복이다.
3. AA1의 "직접 선택 —" 표시가 이 항목에도 기여한다: 바꾼 결과가 카드에 그대로
   보이므로, 바꾸기가 안전한 조작임을 화면이 증명한다.

**테스트**: 변경 버튼 → 시트 열림. (시각 요소이므로 나머지는 실기기 확인 목록으로)

## AA3. 대체 기록 후에도 추가·다른 액션이 가능해야 한다 — 의도 아님, 버그

**피드백**: "대체를 기록하면 다른 액션을 못 하고 무조건 대체에 기록해야 한다.
대체했는데 단백질을 따로 추가했으면 추가 버튼으로 추가할 수 있어야 하는 것 아닌가?
의도된 건가?"

**확인된 현재 동작 — 모델은 되고 UI가 막는다**:

- **데이터 모델·점수는 공존을 완전히 지원한다.** `SlotRecord`는 `substitution`과
  `addition`을 독립 필드로 갖고, `applyAddition`은 대체를 보존하며(스프레드),
  `slotScore`는 "대체 base 점수 + 추가 상한(G2)"으로 정확히 합산한다.
- 막는 것은 시트의 초기 상태 한 줄이다 (DietSlotSheet 62~64행):
  ```ts
  useState<EditMode | null>(record?.substitution ? 'substitution' : null)
  ```
  **대체 기록이 있으면 메뉴를 건너뛰고 대체 편집 폼으로 바로 연다.** "추가로 먹었어요"
  버튼은 메뉴(mode null)에만 있으므로 화면에서 사라진다. "뒤로"를 누르면 메뉴가
  나오긴 하지만, 편집 폼으로 열린 시트에서 뒤로가 메뉴로 간다는 것을 알 방법이 없다 —
  사용자가 "무조건 대체에 기록해야 한다"고 읽은 것이 정확히 그 상태다.

**설계**:

1. **시트는 항상 메뉴로 연다** — 초기 mode를 무조건 `null`로. 62~64행의 조건 제거.
2. 메뉴가 현재 기록 상태를 말하게 한다 (추가와 대칭으로):
   - 대체 기록이 있으면: "대체했어요" → **"대체 수정"**, 옆에 **"대체 지우기"**
     (추가의 118~124행과 같은 패턴).
   - `applyClearSubstitution`이 없다 — **신설한다** (`applyClearAddition`을 거울로:
     substitution만 undefined). 현재 "기록 지우기"(applyClearSlot)는 슬롯 전체를
     지우므로 대체만 걷어낼 방법이 없다.
   - 메뉴 상단에 현재 상태 요약 한 줄: 대체·추가가 있으면 "대체: {text}" / "+ 추가:
     {text}" (DietDayEditor 카드의 표기를 재사용 — 같은 사실은 같은 문구).
3. "전부 먹음"의 기존 의미는 유지한다 (대체·스킵을 지우고 추가는 남긴다 —
   `applyCheckAllItems` 주석의 G2 근거 그대로. 이 동작은 바뀌지 않음을 테스트로 잠근다).

**테스트**: 대체 기록 후 시트를 열면 메뉴가 보인다 (소스 수준: 초기 mode가 record에
의존하지 않는다) · applyClearSubstitution은 substitution만 지운다 (추가·체크 보존) ·
대체+추가 공존 시나리오를 이름 붙여 고정 ("대체했는데 단백질 쉐이크를 추가로 마셨다" —
점수 = 대체 base에 추가 상한 적용, 이미 있는 G2 테스트와 별개로 ops 레벨).

## 구현 순서와 검증

권장 순서: AA3 (가장 작고 독립) → AA1 → AA2 (AA1 위에 얹힘).

검증 관례 (누적):
- `npm run build`로 타입 확인 (`npx tsc --noEmit`은 src 미검사).
- 커밋 메시지 테스트 개수는 실행 출력에서 복사. heredoc은 `<<'MSG'`.
- 완료 후 DEV-RECORD-v1.6.md 작성 (판단이 갈린 지점 + 계획과 다르게 한 것).

범위 제외 (재론 방지):
- 선택 상태의 영속화 (AA1-4 — 다음 날 낡은 선택이 남는 실패가 더 나쁘다)
- 대체 다중 기록 (한 슬롯에 대체 여러 건) — 요구된 적 없고, text 한 줄에 병기 가능

실기기 확인 목록 (구현 후):
1. AA1 — 시트에서 다른 Day 탭 → 시작 안 됨, 카드가 "직접 선택 — 제안은 …"로 바뀜,
   시작 버튼으로 시작
2. AA2 — [변경] 버튼이 보이고 시트가 열림
3. AA3 — 대체 기록된 슬롯을 다시 열면 메뉴가 나오고, "추가로 먹었어요"로 추가 기록,
   카드에 "대체: … / + 추가: …" 둘 다 표시
