## 이 환경에서 확인된 제약 (누적)

1. `npx tsc --noEmit`은 `src`를 검사하지 않는다 → **`npm run build`로 타입 확인**.
2. 개발 브라우저 창은 `visibilityState`가 항상 `hidden`이다 → **앱 전환을 재현할 수 없다.**
   이번 라운드의 3번이 정확히 그 경계에 있다 (§4.4 "증명한 것과 못 한 것").
3. vitest에서 `.css` `?raw`는 빈 문자열.
4. `computer` 클릭은 pane이 hidden이면 타임아웃 → 조작은 `javascript_tool`.
5. RTL이 없다 → 화면 규칙은 순수 함수 + 소스 스캔 2층.
6. `.click()`은 `onPointerDown/Up`을 발화시키지 않는다 / `blur()`는 포커스 없는 문서에서
   이벤트를 만들지 않는다.
7. **소리를 들을 수 없다** → 오디오는 ① 단위 스펙 ② 오디오 그래프 실측(후킹)으로만 확인한다.
   **음색·지각 음량은 여전히 확인 불가**다 (§2.4).
8. `git checkout <파일>`은 커밋되지 않은 작업을 버린다 → `cp` 백업.
9. `innerText` 부분 문자열로 요소를 고르면 안 된다 (v1.9에서 다른 칩을 잡았다).

## 1. FF1 — 카운트인을 설정으로

`tempo.COUNT_IN_SEC = 3` 고정을 `COUNT_IN_OPTIONS = [3, 5, 8]` + `DEFAULT_COUNT_IN_SEC = 5`로
바꾸고 `tempoPositionAt(elapsed, phases, countInSec)`가 받는다.

**기본을 5로 올렸다** (3을 남기되 기본에서 뺐다). 근거: 짧아서 못 따라가는 실패가 길어서
지루한 실패보다 나쁘다 — 준비가 안 된 채 시작하면 첫 반복의 자세가 무너지고, 그건 문서
12장의 보상작용 체크리스트가 막으려는 것이다. 8초는 같은 피드백의 연장이다 (무거운 A그룹
첫 세트는 그립·호흡 세팅에 더 걸린다).

배선: `SessionScreen`(설정 읽기) → `ExerciseCard` → `TempoGuideSheet`. **시트가 설정을 직접
읽지 않는다** — `phases`를 호출부가 넘기는 기존 규칙과 같다 (CC5/CC16에서 세운 것).

실측 (브라우저, 설정 5초): 가이드를 열면 **5 → 4 → 3**으로 센다. 설정 세그먼트는 3·5·8이고
5가 선택돼 있다.

## 2. FF2 — "적극적으로" 올리기

### 2.1 먼저 천장을 확인했다

v1.8의 실효 피크는 **차임 0.36 × 배율 2.2 = 0.792 / 1.0**이었다. 남은 헤드룸이 +2dB뿐이다 —
**게인으로 올릴 자리가 사실상 없었다.** "가장 크게 해도 작다"는 보고가 정확히 그 상태고,
CC8처럼 게인·배율을 또 올리는 것은 이번에는 답이 될 수 없었다.

그래서 피크가 아니라 **귀에 닿는 양**을 올렸다. 네 가지가 실제 지렛대다:

| # | 지렛대 | 조치 | 근거 |
|---|---|---|---|
| 1 | **RMS** | 지수 감쇠 → **유지(sustain) 엔벨로프** | 지수 감쇠는 재생 시간의 대부분을 낮은 진폭으로 보낸다 |
| 2 | **스펙트럼** | 기본파 + 2배음(0.45) + 3배음(0.2) | 폰 스피커가 잘 내는 대역으로 에너지가 퍼진다. **음정은 그대로** |
| 3 | **길이** | 틱 0.11→0.18초, 정지음 0.08→0.14초 | W2 표의 "시간 적분 −4dB" — 200ms 미만은 손해를 본다 |
| 4 | **헤드룸** | 배율 상한 2.2 → 3.0 + 리미터 | 리미터가 클리핑을 막으므로 올릴 수 있다 |

게인도 함께 올렸다 (틱 0.3→0.42 · 차임 0.36→0.5 · 큐 0.3→0.42 · 템포 0.27/0.21→0.38/0.3).

### 2.2 리미터는 음량 조절이 아니라 클리핑 방어다

마스터 체인 `tone들 → 리미터(threshold −2dB · ratio 20 · knee 3) → destination`.

임계값을 낮게 잡고 세게 압축하는 안을 **계산으로 기각**했다: threshold −18 · ratio 8이면
loud 0.62 vs max 0.67로 **볼륨 3단의 차이가 뭉개진다.** 리미터는 하모닉이 쌓여 1.0을 넘을
때만 작동해야 하고, 음량 차이는 배율이 그대로 전달해야 한다.

per-tone 1.0 클램프는 없앴지만 **입력 상한 2.0은 남겼다** — `DynamicsCompressor`는 진짜
리미터가 아니라 소프트니 컴프레서라 극단 입력(설정이 깨져 배율 100)에서 오버슈트한다.

### 2.3 실측 (브라우저 오디오 그래프 후킹)

| 측정 | 값 |
|---|---|
| 한 소리의 오실레이터 | **3개** (기본파 + 2배음) |
| 템포 경계음 2음의 주파수 | **660/1320/1980**, **440/880/1320** — 기본파 유지 |
| 배음 비율 | 0.45 / 0.2 |
| 엔벨로프 (max 볼륨, 수축음) | `set 0.0001 @0` → `ramp **1.14** @8ms` → `set 1.14 @270ms` → `ramp 0.0001 @300ms` |
| 유지 구간 비율 | **87%** (옛 지수 감쇠는 평균 진폭이 피크의 ~37%) |
| 두 경계음의 레벨 차 | 1.14 vs 0.9 — 상대 밸런스 유지 |
| 리미터 | 컨텍스트당 **1개**, threshold −2 · ratio 20 · knee 3 |

유지 구간만으로 같은 피크에서 **평균 진폭이 2배 이상**(≈+7dB) 오른다. 피크는 1.14로 1.0을
넘지만 그것이 리미터를 둔 이유다.

### 2.4 확인할 수 없는 것 (그리고 그것을 아는 것)

**음색과 지각 음량은 이 창에서 확인할 수 없다.** 배음을 얹는 것은 음색 변경이고, CC8에서
같은 종류의 변경(옥타브 하모닉)을 "판단할 수 없는 상태에서 넣지 않는다"며 **보류했던**
것이다. 이번에 넣은 이유는 하나다: **사용자의 판정이 입력으로 들어왔다** ("가장 크게 해도
작다"). 안 들리는 소리는 음색이 좋아도 쓸모가 없고, 실패 방향이 "거슬린다"라면 되돌리기는
`PARTIALS` 한 줄이다 (CC7-R에서 실제로 그렇게 되돌렸다).

3배음까지만 쓴 것도 같은 이유다 — 더 얹으면 사각파에 가까워지고, 이 프로젝트는 거슬리는
소리를 한 번 되돌린 전력이 있다.

### 2.5 음악과의 경쟁 — 앱 밖의 절반

"더 올리면 노래가 너무 커진다"는 **앱이 넘을 수 없는 선**이다. 기기 볼륨은 앱과 음악에
공통으로 걸린다. 남은 방법은 경쟁 상대를 잠깐 줄이는 것(iOS `transient` 세션)이고,
**설정 선택지로 넣되 기본은 껐다** (`설정 → 소리 크기 → 신호음이 음악을 뚫지 못할 때`).

기본을 끄는 이유는 X5다: G8의 실사용 피드백이 "운동 중 스포티파이가 끊긴다"였고 그래서
`ambient`로 갔다. `transient`가 기기·iOS 버전에 따라 덕킹이 아니라 **중단**으로 동작하면
그 회귀가 그대로 재현되는데, **이 창에서는 어느 쪽인지 확인할 방법이 없다.** 무음 스위치를
무시할 가능성도 있어 그 사실까지 설정 문구에 적었다.

## 3. FF3 — "아직도 그대로"인 무음

### 3.1 CC1은 판정만 고쳤다

CC1은 `needsResume`(interrupted 포함)을 만들었고 그 판정은 옳았다. 그런데 **부르는 곳이
`useRestTimer`의 visibilitychange 하나뿐이었다** — 즉 **휴식 타이머가 떠 있는 동안에만**
복구가 돌았다. 세트 중이거나 타이머가 없을 때 앱을 나갔다 오면 아무도 복구를 시도하지
않는다. 실사용에서 앱을 나가는 시점이 하필 그때다 (세트 사이에 메시지를 본다).

**판정을 고치고 배선을 안 고친 것**이 이번 결함의 형태다. 그래서 이번에는 배선을 테스트로
잠갔다 (§3.4).

### 3.2 세 겹으로 고쳤다

1. **전역 배선** — `App`이 `installAudioRecovery()`를 앱 수명 내내 건다:
   `visibilitychange`·`pageshow`(복귀) + **`pointerdown`(모든 사용자 제스처)**.
   제스처 경로가 핵심이다 — iOS는 제스처 안에서만 컨텍스트를 확실히 열어 주고,
   운동 중 사용자는 끊임없이 화면을 만진다. 상태가 running이면 비용은 조건 검사 하나다.
2. **resume 대신 폐기** — 복귀 시 `needsResume`이면 **resume을 시도하지 않고 버린다.**
   iOS는 인터럽트 뒤 컨텍스트를 살려는 주지만 출력이 죽어 있는 사례가 알려져 있고,
   그 상태를 붙들면 "running인데 무음"이 되어 **진단조차 어긋난다.** 다음 제스처가 새로
   만든다. 컨텍스트 누수는 없다 — 만들기 전에 닫는다 (항상 최대 1개).
3. **되살린 뒤에 예약** — `tone()`이 정지 상태면 `resume()`이 끝난 **뒤에** 예약한다.
   예전에는 resume을 부르고 곧바로 정지된 시계의 `currentTime`으로 예약했다.

### 3.3 실측 — 정지 상태에서 소리를 냈을 때

컨텍스트를 강제로 `suspend()`한 뒤(앱 전환의 상태 재현) 템포 경계음을 냈다:

| 측정 | 값 |
|---|---|
| 정지 중 오디오 시계 | 8.805s에서 **멈춤** |
| 클릭 직후 예약된 노드 | **0개** (옛 코드는 여기서 6개를 예약했다) |
| resume 완료 후 예약 | **6개**, 전부 `at ≥ currentTime` |
| 예약 시각 / 그때 시계 | 8.811 / 8.811 |
| resume 소요 (실시간) | **855ms** — 그동안 오디오 시계는 5.3ms만 흘렀다 |
| 진단 카운터 | 생성 1 / 재생성 0 / **정지 후 복구 2** / 유실 0 |

### 3.4 새 스캔 — 배선을 잠갔다

- `installAudioRecovery`를 부르는 파일이 **`App.tsx` 하나**여야 한다
- `useRestTimer`에 `resumeAudio`가 **없어야** 한다 (타이머 안에만 있던 그 결함)
- `resume()` 호출 지점이 **정확히 둘**이어야 한다 (제스처 경로 / 정지 상태 재생 경로)

셋 다 결함 복원으로 실패를 확인했다 (§5).

### 3.5 진단을 남겼다

앱 전환을 이 창에서 재현할 수 없으므로, **실기기에서 사용자가 읽어서 알려줄 수 있는 값**을
설정 → 진단에 넣었다: `생성 / 재생성 / 정지 후 복구 / 컨텍스트 없어 유실` + 오디오 세션 종류.
다음에 또 "소리가 안 난다"가 나오면 이 네 숫자가 원인을 갈라 준다 —
재생성이 오르는데 소리가 안 나면 **원인이 컨텍스트가 아니다.**

## 4. 증명한 것과 증명하지 못한 것

이 구분을 명시하는 이유: CC1이 "고쳤다"고 판정됐는데 현장에서 그대로였다.

| 항목 | 상태 |
|---|---|
| 배선 결함(①)이 실재했다 | **확정** — 소스에 `resumeAudio` 호출부가 하나뿐이었다 |
| 전역 배선이 걸린다 | **실측** — 이벤트 3종 등록·해제 확인 (단위 테스트) |
| 정지 상태에서 예약이 resume 뒤로 밀린다 | **실측** — 클릭 직후 0개 → 이후 6개 |
| 새 게인·엔벨로프·배음이 그래프에 반영된다 | **실측** — §2.3 표 |
| **실기기에서 소리가 실제로 커지는가** | **미확인** (제약 7) |
| **덕킹이 음악을 줄이는가 끊는가** | **미확인** — 기본을 끈 이유 |
| **앱 전환 후 소리가 나는가** | **미확인** (제약 2) — 이번 라운드가 답해야 할 바로 그 질문이다 |

마지막 줄이 정직한 상태다. 세 겹 중 어느 것이 실제로 들을 수 있게 만드는지는 실기기에서만
갈린다. 그래서 진단 카운터를 함께 넣었다.

## 6. 실기기 확인 목록

1. **앱 전환 후 소리** — 세트 중에 다른 앱 갔다 오고, 화면을 한 번 터치한 뒤 휴식 차임을
   들어 본다. **안 들리면 설정 → 진단의 네 숫자를 알려달라** (그 값이 원인을 가른다).
2. **음량** — 음악을 틀고 "가장 크게"로 미리 듣기. 여전히 묻히면 3번.
3. **음악 잠깐 줄이기** — 켜고 미리 듣기. **음악이 멈추면 즉시 끄고 알려달라** (그러면
   `transient`가 이 기기에서 중단으로 동작한다는 뜻이고, 그 경우 다른 길을 찾아야 한다).
4. **음색** — 배음이 얹혀 소리가 두꺼워졌다. 거슬리면 알려달라 (되돌리기는 한 줄이다).
5. **카운트인 5초** — 준비에 충분한지. 8초가 더 맞으면 설정에서 바꿀 수 있다.
6. **템포 정지음** — 0.08 → 0.14초로 길어졌다. B그룹 3-1-1-1에서 뭉개지지 않는지.
