# 지휘자 — 여러 작업 이어서 구현

`agents/COORDINATOR.md`의 1~5절과 7절(진행 파일)을 작업마다 그대로 따른다. 일꾼을 띄울 때마다 턴을 끝내지 말고 "기다리는 법"대로 기다린다.
이 파일은 거기에 더할 것과 6절(마무리)을 대신하는 것이다. PR은 `agents/coordinator/PR.md`를 따른다.

## 대상 고르기

1. 진행 파일 `.reports/run-<PLAN 버전>.md`가 있으면 이어서 하는 일이다. 거기 "다음:" 줄부터 한다. 아래 2~4는 건너뛴다.
2. PLAN의 작업 목록과 "구현 순서" 절, `docs/DEV-RECORD-<PLAN 버전>.md`(있으면)의 완료 기록만 `grep -n`으로 찾아 읽는다.
   기록에 완료로 적힌 작업은 뺀다. 애매하면 넣는다. 구현자가 시작 전 확인에서 "이미 구현됨"으로 걸러낸다.
3. 순서는 PLAN의 "구현 순서" 절을 따른다. **"구현 순서" 절에 작업 ID 없는 선행 단계**(예: "첫 커밋은 골든 테스트")가 있으면
   그 원문을 첫 작업의 구현자 spec 끝에 `선행 단계: <원문>`으로 붙인다. (v1.13에서 이게 빠져 골든 커밋이 KK2 때 들어갔다)
4. 사람에게 목록과 순서를 한 줄로 알리고 **기다리지 않고 바로 시작한다.** 진행 파일을 만든다.

## 작업 트리와 브랜치

- 작업 트리는 **하나만** 만든다. 이름은 `<PLAN 버전>` (Orca가 `Joyanggi/`를 붙인다).
- 모든 작업을 이 브랜치에 순서대로 쌓는다. 앞 작업이 승인돼야 다음 작업을 시작한다("묶음"이면 앞 작업의 구현이 끝나면 시작한다).
- 두 번째 일꾼부터는 COORDINATOR.md "작업 트리 지정"대로 **경로로** 지정한다.
- DESIGN.md "자동 승인"으로 넘어왔다면 plan 브랜치를 기준으로 한다.

## 리뷰 단위

PLAN "구현 순서와 검증" 절의 `리뷰 단위:`를 따른다. 없으면 "작업별"이다.

- **작업별:** 작업마다 구현자 → 리뷰어 순서로 돈다(COORDINATOR.md 그대로).
- **묶음:** 작업마다 구현자만 돌린다. 구현자 `완료`/`이미 구현됨`이면 release하고 바로 다음 작업으로 간다.
  마지막 작업 뒤에 리뷰어를 한 번 띄워 전체를 리뷰한다(`리뷰 범위: <첫 시작 커밋>..HEAD`).
  반려되면 "고칠 것"에 해당하는 작업만 같은 작업 트리에서 다시 구현하고(COORDINATOR.md 4절), 이어서 리뷰어를 다시 띄운다. 두 번째 반려는 멈추는 조건이다.

## 작업마다 더할 것

- 구현자를 띄우기 직전에 `git -C <작업 트리 경로> rev-parse HEAD`로 **시작 커밋**을 진행 파일에 적는다. 위치 기록일 뿐 코드를 읽는 게 아니다.
- 리뷰어 spec 끝에 `리뷰 범위: <시작 커밋>..HEAD`를 붙인다. 안 붙이면 리뷰어가 승인된 앞 작업까지 다시 읽는다.

## 기억을 줄인다

작업 하나가 승인되면 진행 파일 표에 한 줄을 적고, 대화에서는 그 한 줄만 기억한다.
앞 작업의 보고 전문을 다음 작업 spec에 옮기지 않는다.

## 멈추는 조건

아래 중 하나라도 생기면 **전체를 멈추고** gate를 건다. 남은 작업은 시작하지 않는다.

- 구현자 `중단(사람 필요)` 또는 리뷰어 `사람 필요`
- 같은 작업의 두 번째 반려
- 일꾼이 보고 없이 종료, 사용 한도 초과 (한도면 COORDINATOR.md 3절대로 풀리면 이어서)

멈출 때는 진행 파일 표와 멈춘 이유를 전한다.
사람이 "이어서 진행해"라고 하면 **새 세션**에서 이 파일을 다시 읽는다. "대상 고르기" 1번대로 진행 파일에서 이어간다.

## 마무리

마지막 작업이 승인되면 `agents/coordinator/PR.md`대로 PR **하나**를 만든다.
PR 본문 머리 항목: PLAN 파일과 작업 목록, 자동 승인으로 넘어왔으면 "PLAN 포함"·검토자·"설계자가 대신 정한 것" 목록, 작업별 검증 결과.

머지되고 정리가 끝나면 최종 보고를 한 뒤, **끝내지 말고** `agents/coordinator/QUALITY.md`대로 품질 정리를 한 번 돈다. 그게 끝나면 끝낸다.

```
완료: <PLAN 파일> (<n>개 작업)

| 작업 | 결과 | 커밋 | 구현 | 리뷰(반려) | 경미한 점 |
|---|---|---|---|---|---|
| <ID>1 | 승인 | <해시> | 1회 | 1회(0) | 없음 |

<PR.md 5절의 공통 줄>
사람이 할 일: DEV-RECORD의 실기기 확인 목록
```
