# 지휘자 — 설계 작업

`agents/COORDINATOR.md`의 0·1·3·5절은 그대로 따른다. 이 파일은 2·4·6절을 대신한다.

서로 다른 회사의 모델 셋이 같은 설계서를 다룬다. 같은 회사 모델끼리는 놓치는 곳이 겹치기 때문이다.
검토자 둘은 무료 한도로 돌아서 Claude 한도를 쓰지 않는다.

## 일꾼 배치

| 순서 | 역할 | 에이전트 | 모델 | effort | 작업 트리 |
|---|---|---|---|---|---|
| 1 | 설계자 | claude | opus | high | **새 작업 트리** `plan-<PLAN 버전>`, 최신 `main`에서 |
| 2 | 검토자 ① | codex | 기본값 | 기본값 | 설계자와 같은 작업 트리 |
| 3 | 검토자 ② | antigravity | 기본값 | 기본값 | 설계자와 같은 작업 트리 |

- 설계는 품질 차이가 가장 큰 단계라 opus·high를 쓴다. 대신 호출 횟수가 적다.
- 일꾼은 하나씩 띄운다. **검토자 ②에게 ①의 결과를 전하지 않는다.**

## spec

설계자:
```
agents/DESIGNER.md를 읽고 설계해.
주제: <주제 원문> / PLAN 파일: <PLAN 파일> / 작업 ID: <접두사>
끝나면 5절 형식의 보고를 worker_done 요약으로 보내.
```

검토자 (①②같은 문장, `<이름>`만 codex / antigravity로 바꾼다):
```
CLAUDE.md와 agents/PLAN-REVIEWER.md를 읽고 <PLAN 파일>을 설계 검토해.
원래 문제는 <주제 원문>이야. 레포 파일은 고치지 마.
보고는 PLAN-REVIEWER.md 3절대로 .reports/<PLAN 버전>-<이름>.md에 쓰고 --report-path로 알려줘.
```

검토자의 판정과 "고칠 것"은 그 보고 파일에서 읽는다. 보고 파일은 문서라 읽어도 된다.

**검토자가 worker_done 없이 종료돼도 보고 파일이 있으면 정상 완료로 본다.**
Codex는 샌드박스 안에서 `orca` 명령을 실행하지 못해 완료 신호를 못 보낼 때가 있다.
이때 Orca가 "보고 없이 종료" 알림을 보내니, 그 알림을 받으면 보고 파일부터 확인한다.
파일이 있으면 gate를 걸지 말고 일꾼을 release한 뒤 다음 단계로 간다. 파일도 없을 때만 COORDINATOR.md 3절대로 멈춘다.

지휘자는 Orca 작업 트리 폴더를 읽을 수 있게 `--add-dir`로 띄워져 있어야 한다.
읽기가 거부되면 사람에게 "`--add-dir C:\Users\jyg66\orca\workspaces`로 다시 띄워달라"고 알린다.

## 검토 반영 (자동)

검토가 둘 다 끝나면 **설계자에게 반영 판단을 맡긴다.** 지휘자는 어느 지적이 맞는지 판단하지 않는다.
검토자가 보고 없이 끝나거나 한도 초과로 실패하면, 그 검토자는 건너뛰고 남은 보고만 넘긴다.

같은 작업 트리에서 설계자를 다시 띄운다.
```
agents/DESIGNER.md 6절대로 두 검토를 반영해 <PLAN 파일>을 고쳐.
검토 보고: .reports/<PLAN 버전>-codex.md, .reports/<PLAN 버전>-antigravity.md
끝나면 5절 형식으로 보고해.
```

## 사람에게 넘기기

설계자의 보고를 받으면 gate를 걸고 멈춘다. 아래를 원문 그대로 전한다.

```
설계 확정 후보: <PLAN 파일> (작업 <접두사>1~<n>)
브랜치: <브랜치 이름>
반영한 지적: <설계자 보고의 반영 목록 원문>
기각한 지적: <설계자 보고의 기각 목록과 이유 원문>
설계자가 정한 것: <"사람이 정할 것" 중 설계자가 추천안으로 확정한 항목 원문>
사람에게 남은 것: <없으면 "없음">
사람이 할 일: PLAN을 읽고 기각·확정에 이견이 있으면 알려주기. 없으면 머지
```

사람이 이견을 주면 같은 작업 트리에서 설계자를 다시 띄워 DESIGNER.md 4절대로 고치게 한다.

## 마무리

사람이 "이견 없음" 또는 머지했다고 알려주면 끝낸다.

```
설계 확정: <PLAN 파일> (작업 <접두사>1~<n>)
사람이 할 일: main 작업 트리에서 git merge <브랜치> → git push
다음: 새 세션에서 "<PLAN 파일>의 <접두사>1을 진행해"
```
